# Measured transaction weights

Generated by `tools/measure_weight.py`; do not edit by hand. Regenerate from the repository root with:

```
python3 tools/measure_weight.py
```

Each row runs the simulator's own witness builder for the transition (the test suites `tools/test_scripts.py`, `test_mid.py`, `test_min.py` and `test_ccv.py`), captures the witness stack and the transaction of the successful script run, and serialises the whole transaction as Bitcoin Core and btcd do: version, marker and flag, inputs, outputs, one witness stack per input with a CompactSize item count and a CompactSize length prefix per item, locktime. Weight is `3 * stripped size + total size`, and vB = ceil(weight / 4). The tree input's witness is the captured stack, then the script, then a 129-byte control block (the eight-leaf reference set of spec 6.2). Other inputs carry a stub witness of the right size: 108 WU for a P2WPKH fee input (a 72-byte signature and a 33-byte key, as in the model) and 66 WU for a P2TR key-path spend.

The model column is the figure of spec 11, `spec/scripts/sizes.md` and `spec/fee-analysis.md`: script + witness data + 129 + 946 WU, which omits the witness length prefixes and assumes one skeleton (a tree input, a P2WPKH fee input, a tree output, one P2TR payout and a P2WPKH change output). Columns:

* **prefixes**: the tree input's CompactSize item count plus one length prefix per item, script and control block included (1 byte for an item under 253 bytes, 3 bytes up to 65,535). This is the exact amount the model leaves out of the tree input's witness.
* **model + prefixes**: the model with the prefixes added, on the model's 946 WU skeleton.
* **skeleton delta**: the measured weight minus the model with the prefixes added, that is, how far the transaction the test actually builds differs from the 946 WU skeleton (more payout outputs, no change output, no fee input). It is zero when the test's transaction has exactly the model's shape.
* **shape**: inputs and outputs of the measured transaction.

The difference column is measured minus model. For a row whose shape is the model's (2 in / 3 out, one P2TR payout and a P2WPKH change) it is the prefixes alone; elsewhere it also carries the skeleton delta, and a row whose test transaction has no payout or no change measures below the model.

## Per-exit prefix overhead, EXIT_1 (owner), dense D = 16

The witness length prefixes the model omits, for one `EXIT_1` spend in each tier; the measured transaction has exactly the model's skeleton, so this is the whole difference. The FULL and CCV witnesses carry about 40 items, two per level; the MID and MIN witnesses carry each level's sibling as several elements (a hash, a minimal number and its `PADZ` pads), over 160 items, so their overhead is about four times larger.
