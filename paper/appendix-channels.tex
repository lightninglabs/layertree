\section{Channel Leaves: Scripts and Costs}\label{app:channels}

\paragraph{Selectors and context.} Two \op{TX} selectors are used, both
with the collate flag so that one call leaves one blob:
$\mathsf{SEL\_CHAN\_UPD}$ selects version, number of inputs, the current
input's sequence, number of outputs, all output amounts and scripts, and
lock time; $\mathsf{SEL\_CHAN\_SET}$ adds the current input's amount and
scriptPubKey. The per-channel context is
\begin{multline*}
\mathsf{chan\_id} = H_{\mathsf{chanid}}(m \,\|\, \mathsf{owner\_key} \,\|\, \mathsf{le}_{32}(\mathsf{nonce}) \,\|\, x(P_{\mathsf{chan}}) \\
\,\|\, \lesf(C) \,\|\, \mathsf{le}_{32}(\mathsf{epoch}) \,\|\, \mathsf{le}_{32}(\mathsf{csv\_delay})),
\end{multline*}
with $\mathsf{ctx}_{\mathsf{upd}}$ and $\mathsf{ctx}_{\mathsf{set}}$ two
tagged hashes of it, so that an update signature never verifies where a
settlement signature is required. The signed messages are
$\mathsf{SHA256}(\mathsf{ctx} \,\|\, \op{TX}(\mathsf{SEL}))$.

\paragraph{Update output scripts.} The update transaction for state $n$
pays its whole input value to an output $U_n$ with internal key
$P_{\mathsf{chan}}$ (a MuSig2~\cite{musig2,bip327} key of the two parties)
and the two-leaf taptree of Figure~\ref{fig:chan}. A later update binds to
$U_n$ through \textsf{REBIND}$_n$, whose lock-time check admits only
states above $n$; the settlement of state $n$ binds through
\textsf{SETTLE}$_n$ after $\mathsf{csv\_delay}$ blocks, and only to $U_n$
because $\mathsf{SEL\_CHAN\_SET}$ commits the spent script, which embeds
$n$.

\paragraph{Transactions.} The update transaction is version 3, lock time
$S_0 + n$, one input with sequence $\mathtt{0xFFFFFFFD}$, one output of the
full capacity $C$ to $U_n$ and a zero-value pay-to-anchor output; it pays
no fee and is valid whether bound to the funding output or to any earlier
update output, both of value $C$. The settlement is version 3 with input
sequence $\mathsf{csv\_delay}$, outputs for the two balances and each
in-flight HTLC, and an anchor; $b_U + b_V + \sum \mathrm{htlc} = C$. Fees
for both come from a child spending the anchor, so both parties need an
on-chain fee reserve to close unilaterally. The signing order is
settlement before update for each state, as in eltoo.

\paragraph{Force-close cost.} At $D = 16$ dense, $\mathsf{csv\_delay} =
144$ and no HTLCs in flight:

An HTLC output has two leaves, so each sweep carries a 65-byte control
block. The lifetime on-chain footprint of a channel leaf that is
force-closed is therefore about $1{,}680\vB$. For a simple taproot
channel~\cite{taprootchans} priced the same way, the funding transaction
(one P2TR key-path input, the funding output and change) is $154\vB$, the
commitment (a MuSig2 key-path input, two balance outputs and two anchors)
$240\vB$, its anchor child $152\vB$ and the delayed sweep of the
broadcaster's output $138\vB$: about $680\vB$ in all, with both
constructions carrying their fee-bumping children (BOLT~3's anchor
commitment~\cite{bolt3} is $1{,}124\WU$, $281\vB$, in the non-taproot
case). Cooperative closes, splices and lease renewals of a channel leaf
cost one tree transition or nothing. The update transaction cannot be packaged with the exit because
a version-3 transaction may not spend an unconfirmed version-2 parent, so
$G_{\mathrm{exit}}$ in \S\ref{sec:channels} is measured to confirmation,
and the costs above are for a tree of the occupancy that budget allows.

\paragraph{Limits and execution.} Under \texttt{0xC0} every stack element
is at most 520 bytes, including the collated settlement blob of
$156 + 43h$ bytes, so a MID channel carries at most seven HTLC outputs
per state; FULL has no such limit. The scripts and transactions above
run, in both tapleaf versions, on a chain model that enforces BIP-65 and
BIP-68 (149 checks): a leaf leaves a tree by \tr{EXIT}$_1^{=}$, a state
signed before the exit binds to whichever funding output an exit or an
eviction creates, a stale update is answered in the last block of its
window, and both HTLC sweeps confirm at their deadlines. Counted as
those rules count, the budget of \S\ref{sec:channels} has two blocks of
margin: with $G_{\mathrm{exit}} = 72$ and $G_{\mathrm{sweep}} = 2$ the
payee's sweep confirms at $t + 219$ against a bound of 221. A Go mirror
generates the same scripts byte for byte, with channel messages in
Lightning's type-length-value (TLV) encoding.
