\section{The Lean Formalisation}\label{app:lean}

This appendix describes the mechanised model behind \S\ref{sec:security}
in enough detail that a reader can judge what has been proved, under
what assumptions, and what has not. The development is about 4{,}500
lines of Lean~4~\cite{lean4} in eleven modules and depends on nothing but the
core library: no Mathlib, no external tactics. It builds in seconds and
prints an axiom audit for \LeanTheoremCount{} headline theorems; as \texttt{lake build}
prints it, every theorem lists a subset of \lean{propext},
\lean{Quot.sound} and \lean{Classical.choice}, and none lists
\lean{sorryAx}. The code is in the artefact~\cite{layertreerepo}.

The appendix is organised as the Lean development was read against the
paper. Section~\ref{app:lean-heads} lists the headline theorems and states
the main ones; \S\ref{app:lean-abs} says what the model keeps and what it
drops; \S\ref{app:lean-corr} maps every predicate box, algorithm, lemma and
theorem of the paper to its Lean names and shows the key definitions;
the remaining sections give the assumption ledger, the module sizes, the
binding to the output, the encodings and what is not proved.

\LeanTheoremCount{} headline theorems, in eight groups.

The statements of the main ones follow, from the development, with the implicit
arguments the elaborator infers omitted (and some explicit binders
elided in \lean{join\_sound}, \lean{claim\_sound}, \lean{rewrite\_sound}
and \lean{detach\_sound}); the types they use (\lean{Tree},
\lean{Pos}, \lean{fold}, \lean{HashModel}) are in \S\ref{app:lean-abs}.

\lean{t.root} is
the root node of a tree, \lean{t.getSub p} the subtree at position
\lean{p}, \lean{t.setSub p u} the tree with that subtree replaced by
\lean{u}, \lean{t.pathSub p} the honest sibling path, and \lean{t.get},
\lean{t.set}, \lean{t.path} their leaf-level specialisations.

\begin{lstlisting}
theorem fold_pathSub (t : Tree d) (p : Pos d h) :
    fold (t.getSub p).root (t.pathSub p) = t.root
\end{lstlisting}
\iffullversion\else
\begin{lstlisting}
theorem fold_setSub (t : Tree d) (p : Pos d h) (s : Tree h) :
    fold s.root (t.pathSub p) = (t.setSub p s).root

theorem root_inj (t₁ t₂ : Tree d) : t₁.root = t₂.root → t₁ = t₂

theorem fold_sound (t : Tree d) (m : Node H) (π : List (Bool × Node H)) :
    fold m π = t.root →
    ∃ (h : Nat) (p : Pos d h), m = (t.getSub p).root ∧ π = t.pathSub p
\end{lstlisting}

\lean{fold\_sound} is Theorem~\ref{thm:binding}. Its proof is the only
place the hash axioms are used: a non-empty path claims an internal node,
so the tree is not a tip by tag separation, and injectivity of
\lean{hNode} equates both children's hashes and sums with the claimed
ones.
\fi
Note that the conclusion of \lean{fold\_sound} equates \emph{nodes}, so
the sum the prover presented is the true sum of the subtree.

A \lean{Step} is a path, a height, an old node and a new node; it is
valid for roots $r, r'$ when the old node folds to $r$ and the new node to
$r'$, and well formed for depth $d$ when the path has $d - h$ entries.
\lean{Steps} chains steps, each against the root the previous one produced.

\begin{lstlisting}
theorem Step.sound (t : Tree d) (s : Step H) (r' : Node H)
    (hwf : s.WF d) (hv : s.valid t.root r') :
    ∃ p : Pos d s.height, s.old = (t.getSub p).root ∧
      ∀ (u : Tree s.height), u.root = s.new → r' = (t.setSub p u).root
\end{lstlisting}
\iffullversion\else
\begin{lstlisting}
theorem Steps.sum (h : Steps r ss r') :
    r'.sum + oldSum ss = r.sum + newSum ss

theorem Steps.sound (t : Tree d) (h : Steps t.root ss r')
    (hwf : ∀ s ∈ ss, s.WF d) (hg : ∀ s ∈ ss, s.Grounded) :
    ∃ t' : Tree d, t'.root = r'
\end{lstlisting}
\fi

\lean{Steps.sum} is Theorem~\ref{thm:cons} and needs no hash assumption.
\lean{Steps.sound} is Theorem~\ref{thm:ground}; \lean{s.Grounded} says
the new node is the root of some tree of the step's height, which
leaf-level steps satisfy by construction (\lean{grounded\_of\_leaf}) and
which a \tr{JOIN} graft must be given.

The transitions are structures bundling the steps with the output rule
and an opaque authorisation. Their theorems:

\iffullversion\else
\begin{lstlisting}
theorem payable (t : Tree d) (p : Pos d 0) (l : Leaf) (hl : t.get p = some l) :
    (leafStep (t.path p) (some l) none).valid t.root (t.set p none).root ∧
    (t.set p none).root.sum + l.amount = t.root.sum ∧
    ∀ q, q ≠ p → (t.set p none).get q = t.get q

theorem ExitK.no_inflation (h : ExitK exact r blocks r' out0) :
    out0 + payoutSum blocks ≤ r.sum
\end{lstlisting}
\fi
\begin{lstlisting}
theorem ExitK.exact_conservation (h : ExitK true r blocks r' out0) :
    out0 + payoutSum blocks = r.sum
\end{lstlisting}
\iffullversion\else
\begin{lstlisting}
theorem join_sound (t : Tree d) (hwf : path.length + h = d)
    (hj : Join auth h t.root path new r' out0) :
    ∃ p : Pos d h, t.getSub p = Tree.empty h ∧
      out0 = t.root.sum + new.sum ∧
      ∀ u : Tree h, u.root = new → r' = (t.setSub p u).root
\end{lstlisting}
\fi
\begin{lstlisting}
theorem claim_sound (t : Tree d) (hwf₁ : srcPath.length = d)
    (hwf₂ : claimPath.length = d)
    (hc : Claim auth π t.root srcPath claimPath src claim r' out0) :
    out0 = t.root.sum ∧
    ∃ (p₁ p₂ : Pos d 0), t.get p₁ = some src ∧
      (t.set p₁ (claimedSource src claim.amount)).get p₂ = none ∧
      r' = ((t.set p₁ (claimedSource src claim.amount))
              .set p₂ (some claim)).root
\end{lstlisting}

\lean{payable} is Theorem~\ref{thm:pay}. \lean{join\_sound} uses
\lean{root\_inj} (via \lean{eq\_empty\_of\_root}): since \tr{JOIN}$_h$
hard-codes $\Emp_h$ as the old node, the slot it fills is provably the
empty tree, and the theorem gives the successor root for every tree whose
root is the grafted node. \lean{claim\_sound} exposes the drained-source
case: the claim position must be empty in the tree \emph{after} the source
step, which is why a source reduced to zero may host the claim.

The terminal branch of \textsf{Final} and the sparse profile have their
own statements: \lean{terminal\_no\_leaf} (a tree whose root is
$\Emp_D$ holds no leaf, so the terminal branch is reachable only when the
last leaf leaves), \lean{ExitKT.terminal\_conservation} (on that branch
the payouts are at most $S$, exactly $S$ under exact payouts),
\lean{Tree.Sparse.unique} (two leaves with the same owner key and nonce
are the same leaf at the same position) and \lean{sparseJoin\_sound} (a
sparse join lands at the position derived from the leaf, which was
empty, and keeps the tree sparse).

\paragraph{Cohort transitions.} The sweep, \tr{REWRITE}$_h$ and
\tr{DETACH}$_h$ are one step each from a subtree root at a position
\lean{p : Pos d h}; a position inside it is \lean{p.append q}. The sweep
and the rewrite take the published subtrees as values of \lean{Tree h},
since the witness carries their $2^h$ elements and \lean{leaves\_inj}
says those name one tree, so neither needs a \lean{Grounded} hypothesis.
In \lean{Rewrite}, authorisation is a predicate required at every
position whose element changes, and the payouts are those of the leaves
replaced by $\Emp_0$, in position order:

\begin{lstlisting}
theorem rewrite_sound (t : Tree d) (hwf : path.length + h = d)
    (hr : Rewrite h π auth lockTime t.root path old new r' out0 payouts) :
    ∃ p : Pos d h, t.getSub p = old ∧ r' = (t.setSub p new).root ∧
      (∀ q : Pos h 0, t.get (p.append q) = old.get q ∧
        (t.setSub p new).get (p.append q) = new.get q) ∧
      (∀ q : Pos d h, q ≠ p → (t.setSub p new).getSub q = t.getSub q) ∧
      out0 + old.total = t.root.sum + new.total ∧
      out0 + payoutTotal payouts ≤ t.root.sum + new.total

theorem detach_sound (t : Tree d) (hwf : path.length + h = d)
    (hd : Detach auth h t.root path sub r' out0 r₁ out1) :
    ∃ p : Pos d h, out0 + out1 = t.root.sum ∧
      r' = (t.setSub p (Tree.empty h)).root ∧
      r₁ = (t.getSub p).root.hash ∧ out1 = (t.getSub p).total ∧
      ∀ q : Pos h 0, (t.getSub p).get q = t.get (p.append q) ∧
        (t.getSub p).path q = (t.path (p.append q)).drop (d - h)
\end{lstlisting}

\lean{rewrite\_exit\_conservation} specialises \lean{rewrite\_sound} to
an emptied subtree: output~0 plus the payouts equals the input amount.
\lean{detach\_member\_payable} applies \lean{payable} inside the
detached tree to the truncated path. \lean{evictSubtree\_sound} is the
sweep's analogue of \lean{rewrite\_sound} with the new subtree empty, on
either \textsf{Final} branch. \lean{Detach} states its second tree output as a
root hash and an amount rather than generalising \lean{Step}: the
detached output's taptree $m_h$ is a binding fact, outside the step.

\paragraph{The pending-leaf receive.} \lean{Params} carries the optional
reclaim key, and a leaf is \lean{Reclaimable} when its evictor is that key;
a tree without a reclaim key has no reclaimable leaf, and every rule
reduces to its form before the receive. \lean{Merge} (\tr{CLAIM}$^{m}$,
\tr{CLAIM}$^{hm}$) is one step at height~1 over a sibling pair, and
\lean{Reclaim} (\tr{RECLAIM}$_1$) one leaf-level step to $\Emp_0$ with the
deadline compared against a lock-time parameter:

\begin{lstlisting}
theorem merge_sound (t : Tree d) (path : List (Bool × Node H))
    (b : Bool) (src tgt : Leaf) (X : Nat) (r' : Node H) (out0 : Nat)
    (hwf : path.length + 1 = d)
    (hm : Merge auth π t.root path b src tgt X r' out0) :
    out0 = t.root.sum ∧ tgt.ownerKey = src.exitKey ∧
    tgt.exitKey = src.exitKey ∧ tgt.amount < X ∧
    (Tree.tip (mergedSource src (X - tgt.amount))).total + X
      = src.amount + tgt.amount ∧
    ∃ c : Pos d 1, t.get (c.pairAt b) = some src ∧
      t.get (c.pairAt (!b)) = some tgt ∧ ...

theorem reclaim_sound (t : Tree d) (path : List (Bool × Node H))
    (l : Leaf) (r' : Node H) (out0 : Nat) (hwf : path.length = d)
    (hc : Reclaim auth π lockTime t.root path l r' out0) :
    ∃ p : Pos d 0, t.get p = some l ∧ π.Reclaimable l ∧
      l.evictAfter ≤ lockTime ∧ r' = (t.set p none).root ∧
      (∀ q : Pos d 0, q ≠ p → (t.set p none).get q = t.get q) ∧
      out0 + l.amount = t.root.sum
\end{lstlisting}

The tail of \lean{merge\_sound} is elided; it says the successor tree is
\lean{mergeTree}, in which the source is lowered by the draw, with every
field but its amount unchanged and its \lean{seq} included, and the
target is raised to exactly $X$. \lean{reclaim\_only\_flagged} adds that
every leaf that is not reclaimable survives a reclaim and that a tree
with no reclaim key accepts none. \lean{rewrite\_transfer\_sound} is the
analogue for the reclaim form of \tr{REWRITE}$_h$ (spec 7.9 rule~8): an
amount-only decrease of a reclaimable leaf at an even position is
absorbed exactly by its sibling, which the same key owns and exits to,
and \lean{rewrite\_reclaimable\_change} says a reclaimable leaf otherwise
changes only by an amount-only increase or after its deadline, never
needing its owner.

Three theorems state the properties the construction was designed for.
\lean{merge\_stale\_rejected}: if the target already holds $X$ or more, no
merge to $X$ is accepted, so replaying a voucher, or redeeming an older
and lower one after a newer, moves nothing; \lean{merge\_target\_monotone}
gives the accepted case, where the target's level rises to exactly $X$.
\lean{merge\_body\_preserved}: a merge changes no leaf's body, so it voids
no voucher against its source. \lean{merge\_no\_overpay}: along any
history, merges into one target move at most the largest level signed for
it plus what merges move out of it, under the hypothesis that nothing but
a merge lowers the target (the operator's duty to advance the target's
\lean{seq} in any decrease it co-signs, which the scripts do not check),
and every such merge moves value between leaves exiting to one key.
\lean{merge\_cycle\_overpays} is the case the bound allows for, a cycle
between two leaves of one key. The first version of the rules required the
merge target to be owned by the source's exit key but not to exit to it,
and the model showed two consequences: value could leave a key's exits
through a leaf it owned that exits elsewhere, and two leaves each owned by
the other's exit key could merge back and forth. Both rules now require
equal exit keys, after which \lean{Reachable.exit\_value} holds: along any
history of merges and reclaims, the amount held in leaves that are not
reclaimable and exit to one key never decreases.

\paragraph{Histories.} \lean{Trace.lean} composes the transitions along a
whole history. \lean{Trans} is a transition record in the tree's
vocabulary, \lean{Trans.apply} the tree it produces and \lean{Trans.Pre}
what the script requires of the current tree; \lean{Chain} is a history of
accepted spends. \lean{Chain.sound} is the bridge:

\begin{lstlisting}
theorem Chain.sound (t : Tree d) (h : Chain π d t.root r') :
    ∃ (xs : List (Trans d)) (t' : Tree d),
      r' = t'.root ∧ Reachable π t xs t'

theorem Reachable.ledger (h : Reachable π t xs t') :
    t'.total + removedSum xs t = t.total + addedSum xs t
\end{lstlisting}

Every root that a chain of accepted spends reaches from the root of a real
tree is the root of a tree reachable by the transition records, and the
books balance over the records: merges move nothing in or out, and a
reclaim removes its leaf's amount with no payout. \lean{Reachable.dust} and
\lean{Reachable.evictable} carry the dust floor and the evictability of
every leaf through a history, \lean{Reachable.wf} well-formedness, and
\lean{chain\_state} the statement that every on-chain root is the root of
a reachable tree whose every leaf has an accepted exit.


\subsection{Model Abstractions}\label{app:lean-abs}

The model keeps the rules and drops the machinery that carries them out. It
states the \emph{rules} of \S\ref{sec:transitions} as relations over the
objects the scripts manipulate (leaves, nodes, positions, sibling paths,
amounts), with one structure per transition whose fields are the checks of
that transition's predicate box, in protocol order, and it composes the
transitions along histories. What it abstracts, following
\texttt{formal/README.md}:

\begin{itemize}
\item \emph{Tiers and bytecode.} There is no model of tapscript, of
BIP-441 numerics, of \op{TX} or of the BIP-341 message. The four tiers
(FULL, MID, MIN, CCV) differ in how a script computes a rule, not in the
rule, so the model states each rule once; the tier-dependent constants
are parameters of \lean{Params} (\lean{seqFinal}, \lean{dustMin}, the
optional \lean{reclaimKey}). That a script implements the relation is
established by execution (\S\ref{sec:eval}), not by proof.
\item \emph{Authorisation.} Signatures, lock times and the hash lock are
an opaque proposition \lean{auth} of each transition (a predicate on
positions for \lean{Rewrite}). The variants that differ only in what is
signed, \tr{EXIT}$^{t}$, \tr{UPDATE}$^{x}$, \tr{CLAIM}$^{h}$,
\tr{CLAIM}$^{x}$ and \tr{SPLIT}, are therefore the same relation in the
model, and the theorems hold for each. The lock time is a parameter that
the deadline checks compare against, not a height that grows along a
chain.
\item \emph{Transaction fields.} The input and output amounts the scripts
read with \op{TX} are parameters (\lean{out0}); a payout is the pair of
key and amount that output $i$ carries, with its key required to be the
leaf's exit key (\lean{ExitBlock.payoutOk}).
\item \emph{Paths and positions.} Depth is a type index and a position is
\lean{Pos d h}; a sibling path is \emph{root-first}, the reverse of the
witness, which supplies the deepest pair first. In the sparse profile the
position is an arbitrary function of the owner key and nonce; the hash
that derives it is not modelled.
\item \emph{Hashes.} Parameters of a \lean{HashModel}: collision
resistance as injectivity, tag separation as inequalities. Nothing
quantifies an adversary's advantage. Sums are unbounded naturals; the
$2^{64}$ range belongs to the encodings.
\item \emph{What is outside.} Concurrency, mempool policy,
reorganisations and the off-chain protocol are not theorems about hash
trees; the party algorithms of \S\ref{sec:parties} are not formalised,
only the facts about the tree and its histories that their lines rely on.
\end{itemize}

\paragraph{The types.} The definitions below are those the theorems of \S\ref{app:lean-heads} are stated over.

The model states the \emph{rules} of \S\ref{sec:transitions} as
relations over the objects the scripts manipulate: nodes, paths, amounts.
It does not model tapscript bytecode, signatures or keys, and a lock time
is a parameter, not a block height that grows along a chain.
Authorisation is carried as an opaque proposition, and the input and
output amounts the scripts read with \op{TX} are parameters. Three
choices keep the proofs short.

\paragraph{Depth as a type index.} A tree of depth $d$ is
\lean{Tree d}, a perfect binary tree whose tips are \lean{Option Leaf}.
Positions are \lean{Pos d h}, paths from depth $d$ down to a subtree of
height $h$, so that \lean{Pos d 0} addresses a leaf and \lean{Pos d h}
addresses the slot a \tr{JOIN}$_h$ fills. Indexing by both endpoints
avoids all arithmetic on depths: the recursions on \lean{getSub},
\lean{setSub} and \lean{pathSub} pattern-match on the position and the
tree simultaneously, and the one impossible case (a \lean{cons} step below
height~$0$) is dismissed by \lean{Pos.height\_le}.

\begin{lstlisting}
inductive Tree : Nat → Type
  | tip : Option Leaf → Tree 0
  | bin {d : Nat} : Tree d → Tree d → Tree (d + 1)

inductive Pos : Nat → Nat → Type
  | nil {h : Nat} : Pos h h
  | cons {d h : Nat} : Bool → Pos d h → Pos (d + 1) h

def parent (a b : Node H) : Node H :=
  ⟨M.hNode a.hash a.sum b.hash b.sum, a.sum + b.sum⟩

def combine (n : Node H) (x : Bool × Node H) : Node H :=
  if x.1 then parent x.2 n else parent n x.2

def fold (n : Node H) : List (Bool × Node H) → Node H
  | [] => n
  | x :: rest => combine (fold n rest) x
\end{lstlisting}

\paragraph{Root-first paths.} The model orders a sibling path from the
root down, so \lean{fold} is a structural recursion on the list and the
soundness proof is a plain induction. The witness of \S\ref{sec:scripts}
supplies the same pairs leaf-first, because the script consumes the
deepest level first; nothing in the theorems depends on the order.

\paragraph{Hashes as parameters.} Everything is parametric in a class
\lean{HashModel} whose fields are the two hash functions, the zero digest,
and the assumptions the argument uses:

\begin{lstlisting}
class HashModel (Leaf : Type) (H : outParam Type) where
  hLeaf : Leaf → H
  hNode : H → Nat → H → Nat → H
  empty0 : H
  hLeaf_inj : ∀ {l₁ l₂}, hLeaf l₁ = hLeaf l₂ → l₁ = l₂
  hNode_inj : ∀ {a₁ b₁ a₂ b₂ sa₁ sb₁ sa₂ sb₂},
    hNode a₁ sa₁ b₁ sb₁ = hNode a₂ sa₂ b₂ sb₂ →
      a₁ = a₂ ∧ sa₁ = sa₂ ∧ b₁ = b₂ ∧ sb₁ = sb₂
  hNode_ne_hLeaf : ∀ a sa b sb l, hNode a sa b sb ≠ hLeaf l
  hNode_ne_empty : ∀ a sa b sb, hNode a sa b sb ≠ empty0
  hLeaf_ne_empty : ∀ l, hLeaf l ≠ empty0
\end{lstlisting}

Injectivity is collision resistance idealised; the three inequalities are
the tag separation that distinct BIP-340 tags provide. The encodings
module discharges the serialisation half of each injectivity field
(Lemma~\ref{lem:enc}): given SHA-256 collision resistance,
\lean{serializeLeaf\_inj} and \lean{serializeNode\_inj} are what remains.
Nothing quantifies the adversary's advantage; a proof under injectivity
transfers to any adversary that cannot exhibit a collision.

Two entries differ from the paper's boxes in what they check, and the
difference is deliberate. \lean{Update} carries a hypothesis
\lean{new\_dust}, that the written leaf is at least \textsf{DUST\_MIN},
which the script of $\Phi_{\tr{UPDATE}}$ does not check: the spec
(7.8) asks operators not to co-sign such a leaf and the model takes the
operator to honour it, so that \lean{Reachable.dust} holds along a whole
history. And \lean{Claim} states the carve rules as fields
(\lean{evictorKey\_eq}, \lean{evictAfter\_le}, \lean{claim\_dust},
\lean{residual\_dust}), which are checks 7 and 8 of $\Phi_{\tr{CLAIM}}$.

The key definitions follow, as they stand in the Lean source. A step is a
path, a height, an old and a new node, valid when the old node folds to
the current root and the new node to the root written to output~0:

\begin{lstlisting}[style=leansig]
structure Step (H : Type) where
  height : Nat
  path : List (Bool × Node H)
  old : Node H
  new : Node H

def Step.valid (s : Step H) (r r' : Node H) : Prop :=
  fold s.old s.path = r ∧ fold s.new s.path = r'

inductive Steps : Node H → List (Step H) → Node H → Prop
  | nil (r : Node H) : Steps r [] r
  | cons {r r₁ r' : Node H} {s : Step H} {rest : List (Step H)} :
      s.valid r r₁ → Steps r₁ rest r' → Steps r (s :: rest) r'
\end{lstlisting}

The predicates are structures over steps. $\Phi_{\tr{EXIT}}$, $\Phi_{\tr{JOIN}}$,
$\Phi_{\tr{UPDATE}}$ and $\Phi_{\tr{CLAIM}}$ (carve forms):

    (path : List (Bool × Node H)) (old new : Tree h) (r' : Node H) (out0 : Nat)

\subsection{Binding to the Output}

\lean{Binding.lean} records the one cryptographic step outside the hash
model. A structure \lean{BindingModel} carries an abstract
\lean{treeSpk : H → TapRoot → Spk} with the hypothesis that it is
injective in both arguments, and two one-line theorems conclude that a
witness $(r', m')$ passing the scriptPubKey check equals the committed
$(r, m)$, and that the successor output commits to the computed root under
the same $m$. In the deployment the map is
$(r, m) \mapsto x\bigl(P_r + H_{\mathsf{TapTweak}}(x(P_r) \,\|\, m)\cdot G\bigr)$
with $P_r = \mathsf{lift\_x}(x(\NUMS + \Hstate(r) G))$, and the two
x-projections identify a point with its negation. A collision
$(r, m) \ne (r', m')$ yields one of: $x(P_r) = x(P_{r'})$ with $r \ne r'$,
which is a collision in $\Hstate$ or the relation
$\NUMS + tG = -(\NUMS + t'G)$, solvable for the discrete logarithm of
$\NUMS$; $x(P_r) = x(P_{r'})$ with $m \ne m'$, a collision in
$H_{\mathsf{TapTweak}}$; or distinct internal keys with $Q = \pm Q'$.
Write $P_r = \sigma(\NUMS + h G)$ with $\sigma = \pm 1$ and
$h = \Hstate(r)$, and $t = H_{\mathsf{TapTweak}}(x(P_r) \,\|\, m)$. When
the two keys have opposite signs, $Q = \pm Q'$ is a linear relation in
$\NUMS$ and $G$, solvable for the discrete logarithm of $\NUMS$. When
they have the same sign the $\NUMS$ terms cancel and what remains is
$h + \sigma t = h' + \sigma t' \bmod n$, a collision of the composed map
$(r, m) \mapsto \Hstate(r) + \sigma H_{\mathsf{TapTweak}}(x(P_r) \,\|\, m)$:
neither a discrete logarithm nor a collision of either hash. We assume it
hard in the random-oracle model, which is how BIP-341's own binding
argument goes. Making the hypothesis explicit is the point: it is what a
future script change must not break. For the CCV tier
\lean{CCVTweak.binding} decomposes \lean{treeSpk\_inj} into two stage
assumptions, the BIP-443 data tweak of $\NUMS$ by the root and the
taproot tweak by $m$, each of which carries the same case split, so the
binding theorems hold for a CCV tree unchanged (\lean{ccv\_input\_binds}
states the first for the input's own taptree).


\subsection{Encodings}

\lean{Encoding.lean} proves the byte-level facts the design leans on, over
natural-number bytes so that every proof stays within linear arithmetic:
fixed-width little-endian encodings are injective on their range;
\lean{minimalLE (n + 2\^{}(8k)) = leBytes k n ++ [1]} for $n < 2^{8k}$,
which with $k = 8$ is $\encs$ and justifies producing it with one
addition; the 116-byte leaf and the 82-byte node preimage are injective;
and the \lean{SEQ\_FINAL} facts of Lemma~\ref{lem:enc}, computed by
\lean{decide} on a bounded-recursion model of \texttt{CScriptNum}.


\subsection{What Is Not Proved}\label{app:lean-not}

The tapscript bytecode is outside the model. That the scripts of
\S\ref{sec:scripts} implement the relations above is established by
execution: every script of every tier runs in the simulator against a
reference tree with positive and negative cases, and the Go generators are
compared byte for byte with the Python output. A verified interpreter for
the tapscript subset (BIP-441 numerics, \op{TX}, \op{CHECKSIGFROMSTACK})
would close this gap and is a project of a different size. Signatures
are authorisation and deliberately opaque. A lock time is a parameter
that the deadline checks of \lean{Reclaim} and \lean{Rewrite} compare
against; that it is a height that only grows along a chain is not
modelled. Payout
destinations are modelled as the payout the script reads from output
$k$, whose key \lean{ExitBlock.payoutOk} requires to be the leaf's exit
key, for an eviction as for an owner exit (\lean{ExitK.pays\_exit\_key});
that the bytecode makes the output script $\mathrm{P2TR}$ of that key
is established by execution. Lemma~\ref{lem:path} is mechanised for a real tree;
its extension to a path through an opaque node has a paper proof only. Concurrency,
mempool policy, reorganisations and the off-chain protocol are not
theorems about hash trees and belong to a model checker; a design for a
P~\cite{plang} model is in the artefact.
