\begin{abstract}
Constructions that let many users share one Bitcoin output pay at exit
time: a user who leaves publishes $O(\log N)$ transactions, the tree's
interior must exist as pre-signed or template-committed transactions, and
one unresponsive user forces the whole tree on-chain at expiry. We present
\textsc{LayerTree}, in which a single output commits to an off-chain
Merkle-sum tree of balances and tapscript covenants enforce every state
transition. Any member exits, and the operator evicts any expired member,
in \emph{one} transaction whose size grows with the depth of the tree
(about 32 virtual bytes per level) rather than with a path of
transactions: 1{,}020 virtual bytes at depth~16. Membership changes need
no interactive signing round, the shared output never expires, and whole
cohorts are added or swept in one constant-shape transaction.

We state what the shared output does as an ideal functionality with
interfaces \iface{JOIN}, \iface{EXIT}, \iface{EVICT}, \iface{UPDATE} and
\iface{SWEEP}, give an abstract protocol whose covenant predicates realise
it, and compile the predicates to three opcode tiers built only from
proposals already made for Bitcoin (restored string opcodes,
introspection, stack signature checks, elliptic-curve tweaks); the
smallest tier needs \op{CAT} and one point-tweak opcode, recovering
introspection from a generator-key signature. We prove that the abstract
protocol UC-realises the functionality in a global-ledger hybrid model,
with the tree-level lemmas mechanised in Lean~4 and cited inline.
Lightning channels compose with the functionality as leaves whose exit
key is shared, so a hub of $N$ channels occupies one output. A simulator,
a byte-exact Go implementation and 462 executable checks accompany the
design.
\keywords{Bitcoin \and covenants \and Merkle-sum trees \and universal
composability \and payment channels \and formal verification}
\end{abstract}

\section{Introduction}

Payment channels~\cite{lightning} move Bitcoin activity off-chain for
pairs; the open problem is doing it for \emph{groups}: letting $N$ users
share one unspent transaction output (UTXO) without giving up the ability
of each to leave alone. Every deployed or proposed approach pays for the
sharing when it is dissolved. In channel factories~\cite{factories},
CoinPool~\cite{coinpool}, Ark~\cite{ark,clark}, timeout
trees~\cite{timeouttrees,superscalar} and covenant trees built on
\op{CHECKTEMPLATEVERIFY}~\cite{bip119} or
\op{CHECKCONTRACTVERIFY}~\cite{bip443,matt}, the shared output is the root
of a tree of \emph{transactions}. A member who leaves unilaterally must
publish the path from the root to its leaf, $O(\log N)$ transactions each
paying a fee; the interior of the tree must exist in advance as pre-signed
transactions (requiring every member to sign, and to be online) or as
covenant templates; and when the tree expires, reclaiming the funds of a
single unresponsive member means publishing everything.

This paper takes a different route. The tree stays off-chain and is a
tree of \emph{data}, not transactions: a binary Merkle-sum tree of
balances whose root is committed by one output. A member exits by
presenting its leaf and sibling path to the output itself; the spending
script recomputes the root from the proof, checks it against the
commitment, recomputes the root with the leaf removed, and requires the
transaction to recreate the output under the new root with the leaf's
amount paid out. The member needs nobody's signature, the exit is one
transaction, and its size grows with the tree's depth rather than with a
path of transactions. The same covenant lets the operator evict expired
members, graft a pre-built subtree of new members in one step, and sweep
an expired cohort cheaply.

We present the design from the interface inwards. Section~\ref{sec:func}
states, as an ideal functionality in the universal composability (UC)
framework~\cite{canettiUC}, what a shared output should let its members
and operator do and what an adversary may influence. Section~\ref{sec:protocol}
gives an abstract protocol: a data structure, a set of covenant
\emph{predicates} over the spending transaction, and the behaviour of
honest parties, independent of any particular opcode. Section~\ref{sec:scripts}
then realises the predicates against three opcode tiers, from the full
set of restored string opcodes (BIPs~440 and 441~\cite{bip440,bip441}),
introspection (\op{TX}~\cite{optx}), stack signature checks
(\op{CHECKSIGFROMSTACK}~\cite{bip348}) and elliptic-curve
arithmetic~\cite{ecops,bip449} down to \op{CAT} and one point-tweak
opcode; several of these exist on Liquid~\cite{elements}. We propose no
opcode of our own. The separation lets the security argument be made
once, for the predicates, rather than once per tier.

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{The functionality} (\S\ref{sec:func}). $\Ftree$, a shared
  output with per-member balances, parameterised by depth, addressing
  profile, payout rule and a liveness bound $\lat(N)$, with interfaces
  for unilateral exit, eviction, grafting, update, vouchers and sweeps.
\item \textbf{The abstract protocol} (\S\ref{sec:protocol}). A Merkle-sum
  tree committed through a data-tweaked taproot key, and one \emph{step}
  predicate from which every transition is composed, in an
  operator-assigned dense profile and a key-addressed sparse profile.
\item \textbf{Realisation in three opcode tiers} (\S\ref{sec:scripts}).
  Every predicate compiled against the full candidate set, every predicate
  but the cohort sweep against a \texttt{0xC0}-only subset, and the
  single-leaf exit against \op{CAT} and one point-tweak opcode, by
  rebuilding the BIP-341 signature message in script and checking it with
  a generator-key signature. This is an upper bound on the opcodes needed;
  we prove no lower bound.
\item \textbf{A UC security proof with mechanised lemmas}
  (\S\ref{sec:security}, Appendix~\ref{app:uc}). The abstract protocol
  UC-realises $\Ftree$ in a hybrid model with a global ledger and clock
  and an ideal signature functionality, in the idealised hash model. The
  tree-level lemmas the simulator relies on are theorems in Lean~4, cited
  by their statements. The proofs isolated a fact the informal argument
  had blurred: sums are conserved unconditionally, but exits are
  guaranteed only under a real-tree invariant established off-chain.
\item \textbf{Composition with channels} (\S\ref{sec:channels}). Lightning
  channels hosted in leaves whose exit key is shared, with
  prevout-independent commitments emulating \texttt{ANYPREVOUT}, and the
  three conditions under which the channel functionality composes with
  $\Ftree$.
\item \textbf{Implementation and measurement} (\S\ref{sec:eval}). A
  tapscript simulator, a byte-exact Go implementation, and measured costs:
  a $1{,}020\vB$ exit at depth~16, $665\vB$ per batched exit, 158 to
  $203\vB$ per swept leaf.
\end{enumerate}

\section{Background}\label{sec:background}

\paragraph{Bitcoin.}
A pay-to-taproot output~\cite{bip341} commits to an internal key $P$ and
the Merkle root $m$ of a \emph{taptree} of scripts through
$Q = P + H_{\mathsf{TapTweak}}(P \,\|\, m)\cdot G$, and is spent either by
a Schnorr signature~\cite{bip340} under $Q$ or by revealing one script
with its Merkle path (the \emph{control block}) and satisfying it.
Tapscript~\cite{bip342} has no loops, so every ``loop'' below is unrolled
and costs bytes per iteration. BIP-441~\cite{bip441} defines tapleaf
version \texttt{0xC2}, restoring the string opcodes disabled in 2010
(\op{CAT}, \op{SUBSTR}, \op{LEFT}, \op{RIGHT}, bit operations) with
arithmetic on unsigned numbers of any length, metered by
BIP-440~\cite{bip440} (``varops''); BIP-347~\cite{bip347} proposes
\op{CAT} alone in the current version. \op{TX}~\cite{optx} pushes selected
fields of the spending transaction, optionally collated into one hash
preimage; \op{CHECKSIGFROMSTACK}~\cite{bip348} verifies a Schnorr
signature over a stack element; \op{TWEAKADD}~\cite{bip449} computes
$x(P + t G)$, and the EC-ops draft~\cite{ecops} adds point addition,
scalar multiplication and negation. All are proposals. A Merkle-sum
tree~\cite{merkle,mssmt} hashes each node's children with their sums, so
an inclusion proof proves a leaf's contribution to the root sum; sparse
Merkle trees~\cite{smt} address positions by hash.

\paragraph{Composable security.}
We use the UC framework~\cite{canettiUC} with global
subroutines~\cite{guc}. A protocol $\Pi$ \emph{UC-realises} a
functionality $\mathcal{F}$ if for every adversary $\Adv$ there is a
simulator $\Sim$ such that no environment $\Env$ distinguishes $\Pi$ with
$\Adv$ from $\mathcal{F}$ with $\Sim$. Following the composable treatment
of Bitcoin by Badertscher et al.~\cite{bmtz17} we model the chain as a
global ledger $\Gledger$ that accepts transactions satisfying a validity
predicate, orders them at the adversary's discretion within a liveness
bound $\lat_L$, and never reverts them (persistence); time is a global
clock $\Gclock$~\cite{kmtz13} whose rounds are blocks; signatures are the
ideal functionality $\Fsig$~\cite{canettiSig}. Channel functionalities in this model
are given by~\cite{genchannels,gscn}, whose conventions \S\ref{sec:channels}
follows.

\section{The LayerTree Functionality}\label{sec:func}\label{sec:model}

A \emph{tree} has one \emph{operator} and any number of \emph{members}.
Each member owns a \emph{leaf}: a balance and three public keys (an owner
key that authorises the member's actions, an exit key paid on exit, and
an evictor key, normally the operator's, that may remove the leaf after a
lease height). The operator holds no key over the funds, only an
\emph{operator key} that authorises additions and co-signs cooperative
changes. Figure~\ref{fig:func} gives the functionality $\Ftree$; the
parameters are the depth $D$ (the tree has $2^D$ slots), the addressing
\emph{profile} (dense: the operator assigns slots; sparse: a leaf's slot
is a hash of its owner key and nonce), the operator key, the payout rule
$\mathsf{exact}$ (whether an owner may leave part of its balance as fee),
and a liveness bound $\lat(N)$ that grows with the number of members.

\paragraph{What the functionality promises.} Read as guarantees: (G1) \emph{conservation}, $A$ is always the sum
of $T$ and every payout is funded by a removed leaf; (G2) \emph{unilateral
exit}, the owner of any leaf, not opaque, is paid its balance within
$\lat(N)$ with no other party's consent; (G3) \emph{eviction}, after the
lease height the evictor can do the same; (G4) \emph{non-interactive
membership}, \iface{JOIN} and \iface{SWEEP} involve only the operator and
the ledger; (G5) \emph{no expiry}, no interface depends on the age of the
tree. What it does \emph{not} promise is as important: no liveness for
joining, and nothing for a member inside an opaque subtree, one the
operator grafted without revealing its contents; its value is frozen, not
stolen, and \S\ref{sec:parties} makes honest members verify their slot
before funding a join, so an honest member is never opaque.

\paragraph{The liveness bound.} $\lat(N)$ is not a free parameter. Every
call spends and recreates one ledger output, so accepted calls form a
chain; if the ledger admits at most $\kappa$ unconfirmed descendants of an
output (25 under today's policy~\cite{bip125}, a shape cluster
mempool~\cite{clustermempool} changes but does not remove), an adversary
controlling $N - 1$ members can delay an honest call by
$\lceil N/\kappa \rceil$ confirmations of the tree output, each within the
ledger's own bound, giving $\lat(N) = \lat_L(\lceil N/\kappa\rceil + 1)$.
Trees are sized by this bound, not by depth: 10{,}000 channel leaves need
about 400 blocks to force-close. The chain of spends also invites fee
pinning, which the functionality does not model (\S\ref{sec:security}).

\section{The Abstract Protocol}\label{sec:protocol}\label{sec:construction}

The protocol $\Pi$ realising $\Ftree$ has three parts: a data structure
whose root one output commits to (\S\ref{sec:tree}, \S\ref{sec:output}),
one \emph{predicate} per interface over a transaction spending that
output, enforced by the ledger (\S\ref{sec:transitions}), and the
behaviour of honest parties (\S\ref{sec:parties}).

\subsection{The Tree}\label{sec:tree}

We write $\mathsf{le}_{k}(x)$ for the $k$-byte little-endian encoding of
$x$. A leaf is a fixed 116-byte record
\begin{multline*}
\lesf(\mathsf{amount}) \,\|\, \mathsf{exit\_key} \,\|\, \mathsf{owner\_key}
\,\|\, \mathsf{evictor\_key} \\
\,\|\, \mathsf{le}_{32}(\mathsf{evict\_after})
\,\|\, \mathsf{le}_{32}(\mathsf{nonce}) \,\|\, \mathsf{le}_{32}(\mathsf{seq}),
\end{multline*}
with keys as 32-byte x-only points, $\mathsf{evict\_after}$ a block
height, $\mathsf{nonce}$ a per-leaf identifier and $\mathsf{seq}$ a
counter advanced by vouchers (Appendix~\ref{app:claim}). A \emph{node} is
a pair $(h, s)$ of a 32-byte hash and an unsigned sum. A position holding
leaf $\ell$ has node $(\Hleaf(\ell), \ell.\mathsf{amount})$; an empty
position has node $\Emp_0 = (0^{32}, 0)$. The parent of $(h_L, s_L)$ and
$(h_R, s_R)$ is
\[
\bigl(\Hnode(h_L \,\|\, \encs(s_L) \,\|\, h_R \,\|\, \encs(s_R)),\; s_L + s_R\bigr),
\qquad \encs(s) = \lesf(s) \,\|\, \mathtt{0x01}.
\]
Every hash is a BIP-340 tagged hash with its own tag, so no preimage of
one is a preimage of another; $\encs(s)$ is the minimal BIP-441 encoding
of $s + 2^{64}$, so a script produces it from a computed sum with one
addition (Lemma~\ref{lem:enc}). $\Emp_h$ is the node of the empty tree of
height $h$, hard-coded in scripts.

The \emph{sibling path} $\pi$ of a position is the list of $D$ pairs
$(\mathsf{dir}_k, (h_k, s_k))$, one per level, giving the side the
position lies on and the sibling node not taken. $\fold(n, \pi)$ combines
a node $n$ with a path level by level from the bottom up, hashing $n$
with each sibling in the order the direction gives and adding the sums.
Two facts drive the design: the honest path folds a leaf's node to the
root, and folding a \emph{different} node up the \emph{same} path yields
the root of the tree with that position replaced (Theorem~\ref{thm:binding}).

\paragraph{Profiles.}
In the \emph{dense} profile positions are assigned by the operator and a
path carries explicit direction bits; each level costs 88 bytes of script
and 41 bytes of witness. In the \emph{sparse} profile a leaf's position is
the low $D$ bits of $\Hpos(\mathsf{owner\_key} \,\|\, \mathsf{nonce})$,
direction bits are derived in script from the position hash, and empty
siblings are elided from the witness (a one-byte marker in place of a
node; the script substitutes $\Emp_k$), so witness data grows with
$\log_2 N$ rather than with $D$. It is the Merkle-sum sparse Merkle tree
of Taproot Assets~\cite{mssmt} truncated to $D = 32$ or $64$, at 1.8 to
2.7 times the dense per-exit cost (Table~\ref{tab:sizes}).

\subsection{The Tree Output}\label{sec:output}

Let $r$ be the root hash and $S$ the root sum. The tree output is a
taproot output with internal key
$P = \mathsf{lift\_x}\bigl(x(\NUMS + \Hstate(r)\cdot G)\bigr)$, where
$\NUMS$ is the BIP-341 nothing-up-my-sleeve point and $\mathsf{lift\_x}$
the BIP-340 even-$y$ normalisation, so the key path is unspendable and
every spend goes through a script. Its taptree contains one leaf per
supported predicate; the taptree's Merkle root $m$ identifies the rule
set and is constant for the tree's life. We write $\TreeSpk(r, m)$ for
the resulting scriptPubKey; a \emph{tree output} for state $(r, S)$ has
script $\TreeSpk(r, m)$ and amount $S$. Every predicate receives $r$ and
$m$ in its witness, recomputes $\TreeSpk(r, m)$ and checks it against the
spent input's scriptPubKey, binding both the root the proofs are checked
against and the script set the successor carries; without binding $m$ a
spender could recreate the tree under scripts of its choosing. Since every
predicate checks input~0, two trees cannot be spent atomically.

\subsection{The Step and the Transition Predicates}\label{sec:transitions}

Every transition spends the tree output as input~0 and recreates it as
output~0 with the new root and the new total; payouts, if any, occupy
outputs $1, \dots, K$; all other inputs and outputs are unconstrained, so
fees, change and anchors are free. The common core is the \emph{step}
predicate $\mathsf{Step}(r, S; \pi, n_{\mathrm{old}}, n_{\mathrm{new}}; r', S')$:
$\fold(n_{\mathrm{old}}, \pi) = (r, S)$ with $S$ read as input~0's amount
(\tr{CHECK\_OLD}), and $(r', S') = \fold(n_{\mathrm{new}}, \pi)$. A
transition predicate $\Pred_X$ is a sequence of steps, each proving its
old node against the root the previous one produced (\tr{CHECK\_PREV}),
an authorisation condition, and a check that output~0 is
$(S', \TreeSpk(r', m))$ unless $r' = \Emp_D$, in which case the tree is
empty and output~0 is free (\tr{FINAL}). Table~\ref{tab:pred} gives each
interface's predicate; Appendix~\ref{app:scripts} has the step as
pseudocode and as 88 bytes of tapscript.

Signatures must cover all outputs, or a relayer could redirect the fee

optional (Appendix~\ref{app:claim}).

\subsection{Honest Parties}\label{sec:parties}

A member stores its leaf and sibling path and follows every spend of the
tree output; since each witness contains the path it used, the member
updates its own path from the chain alone and never depends on the
operator to exit. Before funding a \iface{JOIN}, or the creation of a
tree, a member verifies its path against the grafted node (or $r_0$) and
the deposited amount; a member who is never added has lost nothing, and
one who skips the check may end up opaque. To exit, a member builds the
transaction of Figure~\ref{fig:exit} with a fee input; it treats
transitions as final only at its confirmation depth, since a
reorganisation invalidates paths derived from dropped ones. The operator
maintains the full tree, assigns slots, signs joins and updates, and
evicts or sweeps expired leaves.

\section{Realisations by Opcode Tier}\label{sec:scripts}

\paragraph{FULL.} With \texttt{0xC2} the leaf is one 116-byte stack
element read with \op{SUBSTR}; sums use arbitrary-length arithmetic and
are padded with $\langle 2^{64}\rangle\ \op{ADD}$ (Lemma~\ref{lem:enc});
one \tr{LEVEL} of the fold is 88 bytes. $\TreeSpk$ is recomputed with the
EC opcodes ($\Hstate(r)\cdot G + \NUMS$, tweaked by the taptree hash,
wrapped in a P2TR script); the \tr{EXIT}$_1$ prologue, with both
introspections and the key recomputation, is under 700 bytes.

\paragraph{MID.} Tapleaf \texttt{0xC0} keeps BIP-342 semantics: no splice
opcodes and 4-byte signed numbers. Fields arrive as separate witness
elements, each checked with \op{SIZE} and re-joined with \op{CAT} before
hashing, and a computed sum is widened to 8 bytes by a witness-supplied
zero pad checked with \op{SIZE} and \op{CAT} (\textsf{PADZ},
Appendix~\ref{app:scripts}); \texttt{MINIMALDATA} policy means lock times
and positions arrive as minimal numbers plus a pad. A cap of $2^{31}$
satoshis per tree and exact payouts are the price of 4-byte arithmetic.
The tier assumes \op{TX} in \texttt{0xC0}, which the draft leaves open;
Liquid~\cite{elements} has per-field introspection in the same role.

\paragraph{MIN: introspection from a signature.}\label{sec:min}
The predicate must read the input's scriptPubKey and amount and
outputs~0 and~1. Without \op{TX} the only opcode that sees the transaction
is \op{CHECKSIG}, and we turn it into introspection. The script
\emph{constructs} the BIP-341 signature message from values it has
derived (the recomputed $\TreeSpk(r,m)$, the input amount, the new tree
output, the payout) and raw witness pieces for everything it does not
constrain (the fee input, prevouts, sequences, version, lock time, tapleaf
hash), hashes it, and demands a Schnorr signature under the generator $G$
with nonce $R = G$. For public key $G$ and nonce $G$ the challenge is
$e = H_{\mathsf{challenge}}(G_x \,\|\, G_x \,\|\, \mathsf{msg})$ and the
verification equation $s\cdot G = (1 + e)\cdot G$ has the unique solution
$s = e + 1 \bmod n$; $G$ has even $y$, so the even-$y$ checks pass. The
script computes $e$ from its constructed message, forms $s$, and calls
\op{CHECKSIG} with signature $G_x \,\|\, s$ and key $G_x$; since
\op{CHECKSIG} hashes the real transaction, the check passes only if the
constructed message equals the real one, up to a collision in the tagged
hashes. The signature authorises nothing; what it adds is binding, resting
on collision resistance of the TapSighash and challenge hashes, outside
the Lean model. Without long arithmetic, $e + 1$ is formed by grinding the
fee input's sequence number until the last byte of $e$ is $\mathtt{00}$
(256 trials on average; Appendix~\ref{app:scripts} has the enforced fields
and the fee-bumping consequences). \tr{EXIT}$_1$ costs $3{,}572$ bytes of
script at $D = 16$ (70\% more than FULL) for $1{,}456\vB$ (43\% more);
vouchers and channel leaves need a signature over stack data and are out
of reach. The result is an upper bound: BIP-342 tapscript, \op{CAT} and
one point-tweak opcode realise the exit predicate; whether a 64-leaf sweep
(16 kB in FULL) fits MIN is open.

\section{Security}\label{sec:security}

We prove that $\Pi$ realises $\Ftree$ in two layers. The tree-level facts
(binding, conservation, payability) are theorems about the abstract
predicates, mechanised in Lean~4~\cite{lean4} in about 1{,}300 lines
without Mathlib (Appendix~\ref{app:lean}) and cited by their statements.
The composable claim is a simulation argument in the hybrid model of
\S\ref{sec:background}, sketched here and given in Appendix~\ref{app:uc}.
We work in the idealised hash model: $\Hleaf$ and $\Hnode$ are injective
on the domains the protocol uses, and digests under different tags never
coincide or equal the zero string; a proof under injectivity holds against
any adversary that cannot exhibit a collision. Predicates and bytecode
correspond by execution (\S\ref{sec:eval}), not proof.

\subsection{Tree-Level Lemmas}

\begin{lemma}[Encodings]\label{lem:enc}
For $s < 2^{64}$, the minimal BIP-441 encoding of $s + 2^{64}$ is
$\lesf(s)\,\|\,\mathtt{01}$; leaf and node serialisations are injective
under the field bounds; the minimal encoding of $2^{32}$ has five bytes
while that of $2^{32}-1$ has four; and the \texttt{CScriptNum} of
$-(2^{31}-1)$ is $\mathtt{ff\,ff\,ff\,ff}$ with successor
$\mathtt{fe\,ff\,ff\,ff}$.
(\lean{enc64\_eq\_minimal},\allowbreak\ \lean{serializeLeaf\_inj},\allowbreak\
\lean{serializeNode\_inj},\allowbreak\ \lean{minimalLE\_two\_pow\_32\_length},\allowbreak\
\lean{scriptNum\_neg\_max31\_succ}.)
\end{lemma}

\begin{theorem}[Binding]\label{thm:binding}
Roots bind trees: two trees of the same depth with equal roots are equal.
Any node $n$ and path $\pi$ with $\fold(n, \pi)$ equal to the root of a
tree $T$ are the root of one of $T$'s subtrees and that subtree's honest
path; in particular the sum in $n$ is the true sum of that subtree, and a
leaf node that verifies with a full-length path is the leaf at that
position.
\end{theorem}
\begin{lstlisting}[style=leansig]
theorem root_inj {d} (t₁ t₂ : Tree d) : (t₁.root : Node H) = t₂.root → t₁ = t₂
theorem fold_sound {d} (t : Tree d) (m : Node H) (π : List (Bool × Node H)) :
    fold m π = t.root → ∃ (h : Nat) (p : Pos d h), m = (t.getSub p).root ∧ π = t.pathSub p
theorem fold_setSub {d h} (t : Tree d) (p : Pos d h) (s : Tree h) :
    fold s.root (t.pathSub p) = ((t.setSub p s).root : Node H)
\end{lstlisting}
\begin{proof}[sketch]
Induction on the path. A non-empty path claims an internal node, so the
tree is not a tip by tag separation. Injectivity of $\Hnode$ on the
parent's preimage equates both children's hashes \emph{and} sums with the
claimed ones, and the induction hypothesis applies to the child the
direction bit selects. This is the only place the hash axioms are used.
\end{proof}

\begin{theorem}[Conservation]\label{thm:cons}
For any sequence of valid steps from $(r, S)$ to $(r', S')$,
$S' + \sum s_{\mathrm{old}} = S + \sum s_{\mathrm{new}}$. Hence for
\tr{EXIT}$_K$, $S' + \sum_k \mathrm{payout}_k \le S$, with equality under
exact payouts; for \tr{JOIN}$_h$, $S' = S + s_{\mathrm{new}}$; for
\tr{UPDATE}, $S' + a_{\mathrm{old}} = S + a_{\mathrm{new}}$; and
\tr{CLAIM} leaves $S$ unchanged. No hash assumption is needed: the
predicate conserves sums whatever nodes it is shown.
\end{theorem}
\begin{lstlisting}[style=leansig]
theorem Steps.sum {r r' : Node H} {ss : List (Step H)} (h : Steps r ss r') :
    r'.sum + oldSum ss = r.sum + newSum ss
theorem ExitK.no_inflation {exact} {r r'} {blocks} {out0} (h : ExitK exact r blocks r' out0) :
    out0 + payoutSum blocks ≤ r.sum      -- ExitK.exact_conservation: equality if exact
\end{lstlisting}

\begin{theorem}[Payability]\label{thm:pay}
For any tree $T$ and position $p$ holding leaf $\ell$, the honest witness
(the leaf, its path, $\Emp_0$) is a valid step from $T$'s root to the
root of $T$ with $p$ emptied, the sum falls by $\ell.\mathsf{amount}$,
and every other position is unchanged.
\end{theorem}
\begin{lstlisting}[style=leansig]
theorem payable {d} (t : Tree d) (p : Pos d 0) (l : Leaf) (hl : t.get p = some l) :
    (leafStep (t.path p) (some l) none).valid t.root (t.set p none).root ∧
    (t.set p none).root.sum + l.amount = t.root.sum ∧ ∀ q, q ≠ p → (t.set p none).get q = t.get q
\end{lstlisting}

\begin{theorem}[Real-tree invariant]\label{thm:ground}
If the current root is the root of a tree and every step is well formed
and \emph{grounded} (its new node is the root of some tree of the step's
height), the final root is the root of a tree of the same depth, namely
the initial tree with each step's subtree replaced. Leaf-level steps are
grounded by construction; a \tr{JOIN} graft is grounded exactly when the
operator's node has a preimage tree.
\end{theorem}
\begin{lstlisting}[style=leansig]
theorem Steps.sound {d} (t : Tree d) {r'} {ss : List (Step H)} (h : Steps t.root ss r')
    (hwf : ∀ s ∈ ss, s.WF d) (hg : ∀ s ∈ ss, s.Grounded) : ∃ t' : Tree d, t'.root = r'
theorem join_sound {auth : Prop} {d h} (t : Tree d) (path) (new r' : Node H) (out0 : Nat)
    (hwf : path.length + h = d) (hj : Join auth h t.root path new r' out0) :
    ∃ p : Pos d h, t.getSub p = Tree.empty h ∧ out0 = t.root.sum + new.sum
      ∧ ∀ u : Tree h, u.root = new → r' = (t.setSub p u).root
\end{lstlisting}

\lean{update\_sound} and \lean{claim\_sound} locate the positions of
\tr{UPDATE} and \tr{CLAIM} the same way; mechanising \tr{CLAIM} showed
that the claim position need only be empty \emph{after} the source step,
which is harmless. Authorisation and lock times decide who may perform a
transition, not what it does; the theorems carry them as an opaque
proposition \lean{auth}, discharged by $\Fsig$ and $\Gclock$ in the
simulation.

\paragraph{Root binding to the output.} The predicates conclude that the
witness root and taptree are the committed ones from
$\TreeSpk(r', m') = \TreeSpk(r, m)$, which needs $\TreeSpk$ injective in
$(r, m)$ (\lean{witness\_root\_binds}); Appendix~\ref{app:lean} reduces
this to the discrete logarithm of $\NUMS$ and collisions in $\Hstate$ or
the taproot tweak hash.

\subsection{The Composable Statement}

Let $\Pi_\tau$ be the protocol of \S\ref{sec:protocol} with the predicates
compiled by tier $\tau$, and let $\Gledger[\Pred_\tau]$ be the global
ledger whose validity predicate, for a spend of a tree output, is that
tier's predicate. Let $\Ftree|_\tau$ be the functionality restricted to
the interfaces $\tau$ realises (Table~\ref{tab:tiers}), with
$\mathsf{exact}$ forced in MID and MIN.

\begin{theorem}[UC realisation]\label{thm:uc}
In the idealised hash model, for each tier $\tau$ and any $D$ and
profile, $\Pi_\tau$ UC-realises
$\Ftree|_\tau[D, \mathsf{profile}, \mathit{pk}_{\mathrm{op}}, \mathsf{exact}, \lat]$
in the hybrid model with $\Gledger[\Pred_\tau]$, $\Gclock$ and $\Fsig$, against
a static adversary corrupting the operator and any subset of members, with
$\lat(N) = \lat_L(\lceil N/\kappa \rceil + 1)$, provided the tree is
created with a real tree $T_0$ whose sum is the funded amount.
\end{theorem}

\begin{proof}[sketch]
The simulator $\Sim$ runs the honest parties internally and translates
between ledger spends and functionality calls. For every spend of the
tree output that $\Gledger$ accepts, $\Sim$ parses the witness, folds each
step's old node up its path, and by Theorem~\ref{thm:binding} recovers
the unique slot it proves (or aborts on a collision, an event the hash
model excludes); it then calls the matching interface of
Figure~\ref{fig:func} on the authoriser's behalf, checking the signatures
with $\Fsig$ (a signature by an honest key the honest party did not issue
is a forgery, excluded by $\Fsig$). Theorem~\ref{thm:ground} gives that the
functionality's tree after the call has exactly the root the transaction
committed, Theorem~\ref{thm:cons} that the amounts the functionality pays
are the transaction's outputs, so the ledger contents agree in both
worlds. Conversely, when $\Ftree$ executes an honest \iface{EXIT} or
\iface{EVICT}, Theorem~\ref{thm:pay} lets $\Sim$ build an accepted real
transaction from the honest party's leaf and path, which it submits
within $\lat(N)$; the contention bound of \S\ref{sec:func} is what makes
$\lat(N)$ sufficient. A graft whose preimage $\Sim$ cannot obtain becomes
an opaque slot in $\Ftree$, matching Theorem~\ref{thm:ground}'s
conditionality. Creation is the base case the covenant cannot enforce,
hence the proviso. The hybrids and the per-tier remarks (MIN's binding
rests additionally on collision resistance of the TapSighash) are in
Appendix~\ref{app:uc}.
\end{proof}

\paragraph{What the theorem leaves out.} The predicates are matched to
the bytecode by 462 executable checks (\S\ref{sec:eval}), not by a
verified compiler; the theorem is about $\Pred_\tau$ as specified. Fee
pinning is outside the ledger model: a low-feerate transition early in the
chain of unconfirmed spends caps the feerate of everything behind it, and
replacing it means paying for its descendants; mitigations are cooperative
batching, anchors so either party can bump, and sizing trees by exit
throughput. This is the design's honest weak spot. The operator can evict
any leaf after its lease, and a cohort at about $160\vB$ per leaf, which
makes griefing cheap; the functionality states this as a capability, and
members who want a hard guarantee buy it with a future lease height.

\section{Channel Leaves as Composition}\label{sec:channels}

A leaf whose exit key is a 2-of-2 between its owner and a counterparty
(normally the operator) can host a payment channel that exists only
off-chain and whose funding output materialises at the payout of the
\iface{EXIT} or \iface{EVICT} that removes the leaf: a tree of $N$ such
leaves is a Lightning hub behind one UTXO, with opening, resizing and
closing costing nothing on-chain except at dispute. In UC terms the
channel protocol runs in the $\Ftree$-hybrid model: it treats the
functionality's payout as its funding transaction. Appendix~\ref{app:channels}
gives scripts, state machine and costs.

\paragraph{Rebindable commitments.}
The funding outpoint is unknown when channel states are signed, and it
changes with every tree transition, so commitment transactions are
authorised by signatures that do not commit to the prevout: \op{TX}
collates the fields the signature covers (version, lock time, the current
input's sequence, the number of inputs, all outputs) behind a per-channel
context constant, and \op{CHECKSIGFROMSTACK} verifies the channel key's
signature over the hash, emulating
\texttt{SIGHASH\_ANYPREVOUT}~\cite{bip118}. The context commits to $m$,
the leaf identity, the channel key, the capacity and a splice epoch, so a
state signed for one channel or capacity never verifies for another.
Penalty transactions cannot be pre-signed against an unknown outpoint, so
channel leaves use the update/settlement ratchet of
eltoo~\cite{eltoo,lnsymmetry}, with zero-fee version-3 transactions and an
ephemeral anchor~\cite{bip431}. Settlement outputs include one per
in-flight HTLC; the deadline budget is
$\mathsf{cltv\_expiry\_delta} \ge G_{\mathrm{exit}} + 3 + \mathsf{csv\_delay} + G_{\mathrm{sweep}}$,
where $G_{\mathrm{exit}}$ is the time to get the exit confirmed including
contention, that is, $\lat(N)$. With $\mathsf{csv\_delay} = 144$ and
$G_{\mathrm{exit}} = 72$ this is about 220 blocks, against 40 to 80 on the
public network.

\paragraph{Composition conditions.}
Let $\Fchan$ be a channel functionality in the style of Generalized
Channels~\cite{genchannels}, whose \iface{CLOSE} pays the latest balances
on the ledger within a bound. Three of $\Ftree$'s interfaces are too
lenient for a leaf whose balance is not the owner's alone, and each
becomes a precondition. (i) A non-exact \iface{EXIT} would let the owner
underfund the channel and hold the counterparty's balance hostage, so
channel leaves live in trees with $\mathsf{exact}$ set, visible in $m$.
(ii) \iface{CLAIM} lets the owner carve value out of a leaf alone, so
channel leaves set $\mathsf{seq}$ to the value whose successor does not
fit in four bytes: $\mathtt{0xFFFFFFFF}$ under BIP-441 numerics but
$\mathtt{0x7FFFFFFF}$ under \texttt{CScriptNum} (Lemma~\ref{lem:enc}).
(iii) Before the lease height the counterparty can enforce nothing
on-chain, so a routing channel leaf sets it to zero, giving the
counterparty \iface{EVICT}; between two members, \tr{UPDATE}$^{x}$ adds
the exit key to \iface{UPDATE}'s authorisers.

\begin{theorem}[Composition, sketch]\label{thm:chan}
In the $(\Ftree, \Gledger, \Gclock, \Fsig)$-hybrid model with conditions
(i) to (iii), the channel-leaf protocol of Appendix~\ref{app:channels}
realises $\Fchan$ with closing bound $\lat(N) + 3 + \mathsf{csv\_delay}$,
for channels whose HTLC deadlines respect the budget above.
\end{theorem}
The argument (Appendix~\ref{app:uc}) reuses the channel-level simulator
of~\cite{genchannels} and uses \iface{EXIT} and \iface{EVICT} to
materialise the funding output; the HTLC deadline argument under $\lat(N)$
is future work. Channel leaves need \op{TX} and \op{CHECKSIGFROMSTACK},
hence FULL or MID; MIN's constructive introspection commits to the prevout.

\section{Evaluation}\label{sec:eval}

\paragraph{Implementation.} A Python tapscript interpreter for both leaf
versions models BIP-441 numerics, \op{TX}, \op{CHECKSIGFROMSTACK}, the
EC opcodes and varops accounting, computes the real BIP-341 signature
message and enforces \texttt{MINIMALDATA}. Every compiled predicate runs
against a reference tree with positive and negative cases per rule
(forged leaf, stale root, attacker-chosen $m$, unconserved amount,
underfunded join, early eviction, evictor shortfall, unsigned update,
voucher replay, over-claim, stale second path, wrong preimage): 369 FULL,
86 MID and 7 MIN checks, failing if any script uses an opcode outside the
candidate set. A Go implementation on \texttt{btcd} and \texttt{lnd}
generates the same scripts, byte-exact against 34 golden vectors, and its
BIP-341 signature hash equals the simulator's, which makes the MIN tier
testable end to end.


\paragraph{Exit cost.} In the dense profile (Figure~\ref{fig:plot};
Table~\ref{tab:sizes} in Appendix~\ref{app:eval} has the raw sizes) a
unilateral exit costs $762\vB$ at $D = 8$ and
$1{,}149\vB$ at $D = 20$: a 4{,}096-fold increase in tree size raises it by
51\%, about $32\vB$ per level. Tier matters more than depth: MID costs
31\% and MIN 43\% more than FULL. The sparse profile at $D = 32$ with
$2^{16}$ members costs about 1.8 times the dense profile at $D = 16$; its
witness grows with $\log_2 N$, not $D$.

\paragraph{Comparison with transaction trees.} The dashed line of
Figure~\ref{fig:plot} is a \emph{model}: a radix-2 tree of $2^D$ leaves
in which every exiter publishes $D$ transactions of about $150\vB$ and a
$111\vB$ claim. Under it the constructions cross near $D = 3$ and
LayerTree is about 60\% smaller at $D = 16$. Two corrections work against
LayerTree: a radix-4 tree halves the levels at about $220\vB$ each
(roughly $1{,}870\vB$ at 65{,}536 leaves, a 45\% gap), and the interior of
a transaction tree is shared, so under mass exit its per-member cost
falls toward one transaction, below LayerTree's $665\vB$ marginal batched
exit. The model prices neither the latency of $D$ sequential
confirmations nor the larger opcode set. LayerTree wins clearly for
isolated exits and eviction, and is comparable or worse for a coordinated
mass exit.

\paragraph{Batching, joins and cohorts.} A second exit in the same
transaction costs $665\vB$ marginally against $1{,}020\vB$ alone. A dense
\tr{JOIN}$_2$ at $D = 16$ is $2{,}713\WU$ of witness whatever the grafted
subtree holds; onboarding cost is dominated by the members' funding inputs
(about $58\vB$ each), which any self-funded construction pays. Sparse
joins cannot graft and cost about $5{,}000\WU$ per leaf.
\tr{EVICT\_SUBTREE}$_4$ removes 13 leaves at $203\vB$ each and
\tr{EVICT\_SUBTREE}$_6$ 51 at $158\vB$, improving with cohort size because
the interior is hashed once.

\paragraph{Fees and budgets.} At $10\sat/\mathrm{vB}$ a $D=16$ exit
costs $10{,}200\sat$: a $1{,}020{,}000\sat$ balance exits for a 1\% fee,
$102{,}000\sat$ for 10\% (Appendix~\ref{app:eval}). Varops usage is 5.6
to 7.7\% of the BIP-440 budget in the dense profile and 2.5 to 4.7\% in
the sparse, falling with depth because the budget scales with weight;
\texttt{0xC0} tiers use one to three of the BIP-342 sigop budget.

\section{Related Work}\label{sec:related}

CoinPool~\cite{coinpool} is the closest prior design: a shared UTXO with
per-user balances and unilateral withdrawal, realised with pre-signed or
covenant-committed transactions, so exit and update remain transaction
trees. Channel factories~\cite{factories} need all $N$ members to sign
every change and publish a tree to exit. Ark~\cite{ark} batches users
into rounds whose virtual outputs are leaves of a pre-signed tree;
covenant Ark~\cite{clark} removes the signing round with CTV or CCV
templates but keeps the tree, its unrolled exit and its expiry. Timeout
trees~\cite{timeouttrees} and SuperScalar~\cite{superscalar} combine
covenant trees with Decker-Wattenhofer factories and laddered expiries;
MATT-style trees~\cite{matt,bip443} replace signatures by templates.
Statechains~\cite{statechains} transfer a whole UTXO off-chain but do not
divide it; \op{VAULT}~\cite{bip345} is an introspection covenant that,
like ours, recreates its output under a modified commitment. In LayerTree
the tree is data rather than transactions: exit is one transaction of
$O(D)$ bytes, the interior needs no pre-signing, the operator can evict,
and the output never expires (Table~\ref{tab:compare},
Appendix~\ref{app:eval}). None states its
guarantees as a functionality; the closest treatments are the ledger model
of Badertscher et al.~\cite{bmtz17} and the channel functionalities
of~\cite{genchannels,gscn}, which we build on.

The Merkle-sum sparse Merkle tree and its compressed proofs come from
Taproot Assets~\cite{mssmt}; here the tree is truncated and verified in
script. The data-tweaked internal key follows
\op{CHECKCONTRACTVERIFY}~\cite{bip443}. The channel state machine is
eltoo~\cite{eltoo}, with \texttt{ANYPREVOUT}~\cite{bip118} emulated by
collated introspection and \op{CHECKSIGFROMSTACK}. Liquid's
tapscript~\cite{elements} has \op{CAT}, \op{CHECKSIGFROMSTACK},
per-field introspection, 64-bit arithmetic and point-tweak verification,
so the MID tier is close to expressible there today;
Simplicity~\cite{simplicity} would express the predicates directly. We
know of no prior use of a generator-key signature with $s = e + 1$ to make
a script's sighash reconstruction binding (\S\ref{sec:min}).

\section{Discussion and Limitations}\label{sec:discussion}

The functionality of \S\ref{sec:func} is deliberately modest: it promises
conservation and the payability of every leaf that is not opaque, and
nothing about being admitted, about grafted subtrees having preimages, or
about the tree having been created correctly; the members' checks are
mandatory and the Lean development shows they are load-bearing. Stating
the design this way made visible that opacity is a state of the
functionality rather than a failure of the protocol, and that $\lat(N)$
is a consequence of the single-UTXO design rather than a tunable: trees
should be sized by exit throughput and sharded. The design is hostage to proposals (a tapleaf version with
restored string opcodes or at least \op{CAT}, \op{TX} in \texttt{0xC0},
the EC opcodes' drafts); every selector and opcode number is a named
constant, and a Liquid prototype of the MID tier is the obvious next
experiment. Future work: a verified compiler from
Table~\ref{tab:pred} to bytecode, closing the gap Theorem~\ref{thm:uc}
leaves; a full proof of Theorem~\ref{thm:chan}; a P model~\cite{plang} of
the off-chain protocol; and completing the MIN tier.

\section{Conclusion}

A shared output can be specified by what it lets its members do: join,
leave alone, be evicted when a lease expires, be swept as a cohort, with
the amount it holds always the sum of its leaves. LayerTree realises that
functionality with a tree that lives off-chain as data rather than
transactions: a one-transaction exit of about a kilobyte, eviction and
cohort sweeps, no pre-signing, no expiry, only opcodes already on the
table. Its guarantees are a simulation argument over mechanically checked
lemmas, its costs are measured, and its price is that all activity funnels
through one UTXO, which bounds how fast a tree can be dissolved.
