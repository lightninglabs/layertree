\begin{abstract}
Transaction-tree constructions that let many users share one Bitcoin
output pay at exit time: a user who leaves publishes $O(\log N)$
transactions, the tree's interior must exist as pre-signed or
template-committed transactions, and one unresponsive user forces the
whole tree on-chain at expiry. In \textsc{LayerTree} a single output commits to an off-chain
Merkle-sum tree of balances and tapscript covenants enforce every state
transition. Any member exits, and the operator evicts any member whose
lease has expired, in \emph{one} transaction of about 32 virtual bytes
per level of depth (1{,}020 at depth~16). Adding members needs only the
operator's signature on the covenant (a self-funded cohort still signs
its inputs together), the shared output never expires (members hold
leases), and a cohort is added or swept in one transaction.

We state what the shared output does as an ideal functionality, give an
abstract protocol whose covenant predicates realise it, and compile the
predicates to four tiers of opcodes already proposed for Bitcoin, some
assumed in a tapleaf version their proposals do not define; the smallest
tier needs \op{CAT} and one point-tweak opcode, recovering introspection
from a generator-key signature. We prove that the abstract protocol
UC-realises the functionality in a global-ledger hybrid model, under a
stated assumption on how many competing spends of the shared output can
confirm ahead of an honest one, with the tree-level lemmas mechanised in
Lean~4. Lightning channels compose with the functionality as leaves whose
exit key is shared, so a hub sized by exit throughput occupies one
output. A simulator, a byte-exact Go implementation and 2{,}083
executable checks accompany the design.
\keywords{Bitcoin \and covenants \and Merkle-sum trees \and universal
composability \and payment channels \and formal verification}
\end{abstract}

\section{Introduction}

Payment channels~\cite{lightning} move Bitcoin activity off-chain for
pairs; the open problem is doing it for \emph{groups}: letting $N$ users
share one unspent transaction output (UTXO) without giving up the ability
of each to leave alone. Most deployed or proposed approaches pay for the
sharing when it is dissolved. In channel factories~\cite{factories},
Ark~\cite{ark,clark}, timeout trees~\cite{timeouttrees,superscalar} and
covenant trees built on \op{CHECKTEMPLATEVERIFY} (CTV)~\cite{bip119} or
\op{CHECKCONTRACTVERIFY}~\cite{bip443,matt}, the shared output is the root
of a tree of \emph{transactions}. A member who leaves unilaterally
publishes the path from the root to its leaf, $O(\log N)$ transactions
each paying a fee; the interior must exist in advance as pre-signed
transactions (every member signs, online) or covenant templates; and
when the tree expires, reclaiming the funds of one unresponsive member
means publishing everything. Payment-pool opcode proposals
(\texttt{OP\_TAPLEAF\_\allowbreak UPDATE\_\allowbreak VERIFY}~\cite{tluv}, CoinPool's
\op{MERKLESUB}~\cite{coinpool}, \op{EVICT}~\cite{opevict}) target
one-transaction withdrawal instead, with purpose-built opcodes.

This paper takes a different route. The tree stays off-chain and is a
tree of \emph{data}: a binary Merkle-sum tree of balances whose root one
output commits to. A member exits by presenting its leaf and sibling path
to the output itself; the script recomputes the root from the proof,
checks it against the commitment, recomputes it with the leaf removed,
and requires the transaction to recreate the output under the new root
with the leaf's amount paid out. The member needs nobody's signature, and
the exit is one transaction whose size grows with the tree's depth. The
same covenant lets the operator evict members whose lease has expired,
graft a pre-built subtree of new members in one step, and sweep an
expired cohort cheaply.

We present the design from the interface inwards: an ideal functionality
in the universal composability (UC) framework~\cite{canettiUC}
(\S\ref{sec:func}); an abstract protocol of covenant \emph{predicates}
and honest-party behaviour, independent of opcodes (\S\ref{sec:protocol});
and four realisations by opcode tier (\S\ref{sec:scripts}), from restored
string opcodes (BIPs~440 and 441~\cite{bip440,bip441}), introspection
(\op{TX}~\cite{optx}), stack signature checks
(\op{CHECKSIGFROMSTACK}~\cite{bip348}) and elliptic-curve
arithmetic~\cite{ecops,bip449} down to \op{CAT} and one point-tweak
opcode, plus one built on \op{CHECKCONTRACTVERIFY}~\cite{bip443}. We
propose no opcode for this design, but the tiers are not deployable as
proposals stand: MID and both CCV variants assume opcodes in a tapleaf
version their proposals do not define, and two drafts claim the same
opcode numbers (\S\ref{sec:scripts}).\ifanon\else{} The elliptic-curve
draft~\cite{ecops} is by the author of this paper.\fi{} The separation
lets the security argument be made once, for the predicates.

\paragraph{Contributions.} (1) $\Ftree$, with interfaces for exit,
eviction, grafting, update, vouchers and sweeps, and liveness under an
explicit contention assumption. (2) An abstract protocol built from one
\emph{step} predicate over a Merkle-sum tree. (3) Every predicate
compiled in three tiers, and the exit in a fourth (MIN) that rebuilds
the BIP-341 message in script and checks it with Poelstra's generator-key
signature~\cite{catschnorr}; an upper bound on the opcodes needed. (4) A
UC proof in a global-ledger hybrid model with the tree-level lemmas
mechanised in Lean~4, which isolated that sums are conserved
unconditionally but exits are guaranteed only for members who verified
their path. (5) Lightning channels as leaves, and the conditions under
which they compose. (6) A simulator, a byte-exact Go implementation, and
measured costs: a $1{,}020\vB$ exit at depth~16, $665\vB$ for a second
exit in the same transaction, 158 to $203\vB$ per swept leaf.

\section{Background}\label{sec:background}

\paragraph{Bitcoin.}
A pay-to-taproot output~\cite{bip341} commits to an internal key $P$ and
the Merkle root $m$ of a \emph{taptree} of scripts through
$Q = P + H_{\mathsf{TapTweak}}(P \,\|\, m)\cdot G$, and is spent either by
a Schnorr signature~\cite{bip340} under $Q$ or by revealing one script
with its Merkle path (the \emph{control block}) and satisfying it.
Tapscript~\cite{bip342} has no loops, so every ``loop'' below is unrolled.
BIP-441~\cite{bip441} defines tapleaf version \texttt{0xC2}, restoring
the string opcodes disabled in 2010 (\op{CAT}, \op{SUBSTR}, \op{LEFT},
\op{RIGHT}, bit operations) with unsigned numbers of any length, metered
by BIP-440~\cite{bip440} (``varops''); BIP-347~\cite{bip347} proposes
\op{CAT} alone in the current version, \texttt{0xC0}. \op{TX}~\cite{optx}
pushes fields of the spending transaction, optionally collated into one
hash preimage; \op{CHECKSIGFROMSTACK} (CSFS)~\cite{bip348} verifies a
signature over a stack element; \op{TWEAKADD}~\cite{bip449} computes
$x(P + t G)$, and the EC-ops draft~\cite{ecops} adds point arithmetic.
All are proposals. Sizes are in virtual bytes (vB), a quarter of a
transaction's weight in weight units (WU), where a witness byte weighs
one unit and any other byte four. A Merkle-sum tree~\cite{merkle,mssmt}
hashes each node's children with their sums, so an inclusion proof
proves a leaf's contribution to the root sum.

\paragraph{Composable security.}
We use the UC framework~\cite{canettiUC} with global
subroutines~\cite{guc}. A protocol $\Pi$ \emph{UC-realises} a
functionality $\mathcal{F}$ if for every adversary $\Adv$ there is a
simulator $\Sim$ such that no environment $\Env$ distinguishes $\Pi$ with
$\Adv$ from $\mathcal{F}$ with $\Sim$. Following Badertscher et
al.~\cite{bmtz17} the chain is a global ledger $\Gledger$ that accepts
transactions satisfying a validity predicate, orders them at the
adversary's discretion within a liveness bound $\lat_L$, and never
reverts them; time is a global clock $\Gclock$~\cite{kmtz13} whose rounds
are blocks; signatures are the ideal functionality
$\Fsig$~\cite{canettiSig}; channels follow~\cite{genchannels,gscn}.

\section{The LayerTree Functionality}\label{sec:func}\label{sec:model}

A \emph{tree} has one \emph{operator} and any number of \emph{members}.
Each member owns a \emph{leaf}: a balance and three keys (an owner key
that authorises the member's actions, an exit key paid on exit, and an
evictor key, normally the operator's, that may remove the leaf after a
lease height). The operator holds no key over the funds, only an
\emph{operator key} that authorises additions and co-signs cooperative
changes. Figure~\ref{fig:func} gives $\Ftree$; its parameters are the
depth $D$, the addressing \emph{profile} (dense: the operator assigns
slots; sparse: a slot is a hash of the owner key and a nonce), the
operator key, the payout rule $\mathsf{exact}$ (whether an owner may leave
part of its balance as fee), and the liveness bound $\lat$ below.
$\Ftree$ is protocol-aware, as in Generalized
Channels~\cite{genchannels}: it builds an honest party's transaction from
a fee coin the caller names and posts it.

\paragraph{What the functionality promises.} (G1) \emph{Conservation}:
$A$ is the sum of $T$ and every payout is funded by a removed leaf.
(G2) \emph{Unilateral exit}: the owner of a known leaf is paid its
balance with no other party's consent; no party can prevent the exit
except by outbidding it, and under [C] below it takes effect within
$\lat(q)$. (G3) \emph{Eviction}: after the lease height the evictor can
do the same, and since a carve keeps the evictor and a lease no later,
this holds per balance. (G4) \emph{Operator-only membership}:
\iface{JOIN} and \iface{SWEEP} need the operator and no member. (G5)
\emph{No expiry of the shared output}, though each leaf has a lease.
Not promised: liveness for joining, and anything for value under an
opaque node never revealed (frozen, not stolen); honest members verify
their path before funding (\S\ref{sec:parties}), so their leaves are
known.

\paragraph{The liveness bound.} Every call spends and recreates one
ledger output, and an honest call can be overtaken by any number of
valid conflicting spends (a corrupt member alone can carve its balance
back and forth), so the delay does not follow from the ledger model; we
state it under an assumption whose parameters we do not derive. \emph{[C] (contention):} at most
$\kappa \ge 1$ spends of a tree output confirm per block, and while an
honest transition is pending at the prevailing feerate at most $\beta$
conflicting adversarial spends confirm ahead of it. $\kappa$ is mempool
policy: 25 under Bitcoin Core's ancestor and descendant
limits~\cite{corepolicy}, a cluster limit under cluster
mempool~\cite{clustermempool}, and as low as 1 once anyone hangs
descendants off a payout or change output. $\beta$ is economic, the
adversary's fee budget against the honest bid; unbounded, it makes exit
a fee auction. Under [C] an honest call with $q$ honest calls queued
ahead takes effect within
$\lat(q) = \lat_L(\lceil (\beta + q)/\kappa \rceil + 1)$ rounds, $\lat_L$
being the ledger's liveness parameter. Cooperatively ($\beta = 0$,
$\kappa = 25$, $\lat_L = 1$ block) a tree drains 25 exits per block, so
10{,}000 channel leaves closing at once take 400 blocks: trees are sized
by exit throughput, not depth.

\section{The Abstract Protocol}\label{sec:protocol}\label{sec:construction}

The protocol $\Pi$ has a data structure whose root one output commits
to, one \emph{predicate} per interface, enforced by the ledger, and the
behaviour of honest parties.

\subsection{The Tree}\label{sec:tree}

We write $\mathsf{le}_{k}(x)$ for the $k$-byte little-endian encoding of
$x$. A leaf is a fixed 116-byte record
\begin{multline*}
\lesf(\mathsf{amount}) \,\|\, \mathsf{exit\_key} \,\|\, \mathsf{owner\_key}
\,\|\, \mathsf{evictor\_key} \\
\,\|\, \mathsf{le}_{32}(\mathsf{evict\_after})
\,\|\, \mathsf{le}_{32}(\mathsf{nonce}) \,\|\, \mathsf{le}_{32}(\mathsf{seq}),
\end{multline*}
with keys as 32-byte x-only points, $\mathsf{evict\_after}$ a block
height, $\mathsf{nonce}$ a per-leaf identifier and $\mathsf{seq}$ a
counter advanced by vouchers (Appendix~\ref{app:claim}). A \emph{node} is
a pair $(h, s)$ of a 32-byte hash and an unsigned sum. A position holding
leaf $\ell$ has node $(\Hleaf(\ell), \ell.\mathsf{amount})$; an empty
position has node $\Emp_0 = (0^{32}, 0)$. The parent of $(h_L, s_L)$ and
$(h_R, s_R)$ is
\[
\bigl(\Hnode(h_L \,\|\, \encs(s_L) \,\|\, h_R \,\|\, \encs(s_R)),\; s_L + s_R\bigr),
\qquad \encs(s) = \lesf(s) \,\|\, \mathtt{0x01}.
\]
Every hash is a BIP-340 tagged hash with its own tag; $\encs(s)$ is the
minimal BIP-441 encoding of $s + 2^{64}$, produced from a computed sum
with one addition (Lemma~\ref{lem:enc}). $\Emp_h$ is the node of the
empty tree of height $h$.

The \emph{sibling path} $\pi$ of a position is the list of $D$ pairs
$(\mathsf{dir}_k, (h_k, s_k))$, one per level, giving the side the
position lies on and the sibling node not taken. $\fold(n, \pi)$ combines
a node with a path from the bottom up, hashing with each sibling in the
order the direction gives and adding the sums. The honest path folds a
leaf's node to the root, and folding a \emph{different} node up the
\emph{same} path yields the root with that position replaced
(Theorem~\ref{thm:binding}).

\paragraph{Profiles.}
In the \emph{dense} profile positions are assigned by the operator and a
path carries explicit direction bits; each level costs 88 bytes of script
and 41 bytes of witness. In the \emph{sparse} profile a leaf's position is
the low $D$ bits of $\Hpos(\mathsf{owner\_key} \,\|\, \mathsf{nonce})$,
direction bits are derived in script from the position hash, and empty
siblings are elided from the witness (the script substitutes $\Emp_k$),
so witness data grows with $\log_2 N$ rather than with $D$. It is the
Merkle-sum sparse Merkle tree of Taproot Assets~\cite{mssmt} truncated to
$D = 32$ or $64$, at 1.7 to 2.8 times the dense per-exit cost with
$2^{16}$ members (Table~\ref{tab:sizes}). Dense is the default, and the
rest of the paper measures it unless it says otherwise.

\subsection{The Tree Output}\label{sec:output}

Let $r$ be the root hash and $S$ the root sum. The tree output is a
taproot output with internal key
$P = \mathsf{lift\_x}\bigl(x(\NUMS + \Hstate(r)\cdot G)\bigr)$, where
$\NUMS$ is the BIP-341 nothing-up-my-sleeve point and $\mathsf{lift\_x}$
the BIP-340 even-$y$ normalisation, so the key path is unspendable and
every spend goes through a script. Its taptree has one leaf per
predicate; its Merkle root $m$ identifies the rule set and is fixed for
the tree's life. A \emph{tree output} for state $(r, S)$ has scriptPubKey
$\TreeSpk(r, m)$ and amount $S$. Every predicate recomputes
$\TreeSpk(r, m)$ from its witness and checks it against the spent input,
binding the root the proofs are checked against and the script set the
successor carries. FULL, MID and MIN predicates read input~0, so two such
trees cannot be spent in one transaction; a CCV tree's input may sit at
any index.

\subsection{The Step and the Transition Predicates}\label{sec:transitions}

Every transition spends the tree output and recreates it as output~0
with the new root and total; payouts occupy outputs $1, \dots, K$; other
inputs and outputs are free, for fees, change and anchors. The core is
the \emph{step}: $\fold(n_{\mathrm{old}}, \pi) = (r, S)$ with $S$ the
input's amount (\tr{CHECK\_OLD}), and $(r', S') = \fold(n_{\mathrm{new}},
\pi)$. A predicate $\Pred_X$ is a sequence of steps, each proving its old
node against the previous step's root (\tr{CHECK\_PREV}), an
authorisation, and a check that output~0 is $(S', \TreeSpk(r', m))$
unless the tree is now empty (\tr{FINAL}). Table~\ref{tab:pred} gives
each interface's predicate; Appendix~\ref{app:scripts} gives the step in
pseudocode and tapscript.

\subsection{Honest Parties}\label{sec:parties}

A member stores its leaf and path and follows every spend of the tree
output; each witness contains the path it used, so the member updates its
own path from the chain alone. Before funding a \iface{JOIN} or a
creation, it verifies its path against the grafted node (or $r_0$) and
the deposit; one who skips the check may end up under an opaque node. A
self-funded graft therefore needs every funder to sign one transaction
after the cohort is fixed, an abort-and-retry round like an Ark round or
a coinjoin; in an operator-funded graft the operator fronts the value and
members pay it off-chain. To exit, a member builds the transaction of
Figure~\ref{fig:exit} with a fee input. Its signature commits to the tree
outpoint, which every transition changes, so an exit cannot be pre-signed
or delegated: the owner key must be online to rebuild it after a
competing spend and to bump its fee. Transitions are final at the
member's confirmation depth. The operator keeps the full tree, assigns
slots, signs joins and updates, and evicts or sweeps expired leaves.

\paragraph{FULL and MID.} With \texttt{0xC2} the leaf is one 116-byte
stack element read with \op{SUBSTR}, sums use arbitrary-length arithmetic,
one \tr{LEVEL} of the fold is 88 bytes, and $\TreeSpk$ is recomputed with
the EC opcodes; replacing the splice and EC opcodes by \op{CAT} and
\op{TWEAKADD} costs 2{,}378 bytes of script at $D = 16$ against 2{,}101.

Under \texttt{0xC0} (MID) fields arrive as separate witness elements,
checked with \op{SIZE} and joined with \op{CAT}, and a computed sum is
widened to 8 bytes by a witness-supplied zero pad
(Appendix~\ref{app:scripts}); a cap of $2^{31}$ satoshis (21.47\,BTC) per
tree and exact payouts are the price of 4-byte arithmetic.

\paragraph{MIN: introspection from a signature.}\label{sec:min}
Without \op{TX} the only opcode that sees the transaction is
\op{CHECKSIG}. The script \emph{constructs} the BIP-341 signature message
from values it has derived (the recomputed $\TreeSpk(r,m)$, the input
amount, the new tree output, the payout) and raw witness pieces for what
it does not constrain, and demands a Schnorr signature under the
generator $G$ with nonce $G$, Poelstra's construction~\cite{catschnorr}:
the challenge is $e = H_{\mathsf{challenge}}(G_x \,\|\, G_x \,\|\,
\mathsf{msg})$, and $s G = (1 + e) G$ has the unique solution
$s = e + 1 \bmod n$. The script computes $e$ from its message and calls
\op{CHECKSIG} with signature $G_x \,\|\, s$ and key $G_x$; since
\op{CHECKSIG} hashes the real transaction, it passes only if the two
messages are equal, which is assumption [MIN]. Without long
arithmetic, $e + 1$ is formed by grinding the fee input's sequence number
until $e$ ends in $\mathtt{00}$ (256 trials on average, repeated on every
fee bump; Appendix~\ref{app:scripts}). What is new is the use: the
field-by-field enforcement and the signature as a tier's only
introspection. \tr{EXIT}$_1$ costs
$3{,}572$ bytes of script at $D = 16$ (70\% more than FULL) and
$1{,}456\vB$ (43\% more); vouchers and channel leaves need a signature
over stack data and are out of reach, \tr{SPLIT} is not ($6{,}501$
bytes). Whether a 64-leaf sweep (16 kB in FULL) fits MIN is open.

\paragraph{CCV: binding by opcode.}\label{sec:ccv}
\op{CHECKCONTRACTVERIFY}~\cite{bip443} replaces every taproot-key
recomputation of FULL: one call binds the old root to the input under
the input's own taptree, one commits output~0 to the new root with the
residual assigned, one per payout asserts a P2TR of the leaf's exit key
and deducts its amount. The state key becomes the BIP-443 data tweak of
$\NUMS$ by the root; the fold and the authorisation are FULL's, in either
numeric encoding, and $r$ and $m$ leave every witness. One \op{TX} read
per constrained amount survives, hence exact payouts.

\section{Security}\label{sec:security}

The tree-level facts are theorems about the abstract predicates,
mechanised in Lean~4~\cite{lean4} in about 1{,}900 lines without Mathlib
(Appendix~\ref{app:lean}) and cited by name; the composable claim is a
simulation argument in the hybrid model of \S\ref{sec:background},
sketched here and given in \lifted{app:uc}. We work in the idealised hash
model: $\Hleaf$ and $\Hnode$ are injective on the domains the protocol
uses, and digests under different tags never coincide or equal the zero
string. Predicates and bytecode correspond by execution
(\S\ref{sec:eval}), not proof.

\subsection{Tree-Level Lemmas}

\begin{lemma}[Encodings]\label{lem:enc}
For $s < 2^{64}$ the minimal BIP-441 encoding of $s + 2^{64}$ is
$\lesf(s)\,\|\,\mathtt{01}$; leaf and node serialisations are injective;
$2^{32}$ has a five-byte minimal encoding and $2^{31}$ a five-byte
\texttt{CScriptNum}, while $-(2^{31}-1)$ is $\mathtt{ff\,ff\,ff\,ff}$
with successor $\mathtt{fe\,ff\,ff\,ff}$.
(\lean{enc64\_eq\_minimal},\allowbreak\ \lean{serializeLeaf\_inj},\allowbreak\
\lean{serializeNode\_inj},\allowbreak\ \lean{minimalLE\_two\_pow\_32\_length},\allowbreak\
\lean{scriptNum\_two\_pow\_31\_length},\allowbreak\
\lean{scriptNum\_neg\_max31\_succ}.)
\end{lemma}

\begin{theorem}[Binding]\label{thm:binding}
Roots bind trees: two trees of the same depth with equal roots are equal.
Any node $n$ and path $\pi$ with $\fold(n, \pi)$ equal to the root of a
tree $T$ are the root of one of $T$'s subtrees and that subtree's honest
path; in particular the sum in $n$ is the true sum of that subtree, and a
leaf node that verifies with a full-length path is the leaf at that
position. (\lean{root\_inj}, \lean{fold\_sound}.)
\end{theorem}
\iffullversion
\begin{lstlisting}[style=leansig]
theorem root_inj {d} (t₁ t₂ : Tree d) : (t₁.root : Node H) = t₂.root → t₁ = t₂
theorem fold_sound {d} (t : Tree d) (m : Node H) (π : List (Bool × Node H)) :
    fold m π = t.root → ∃ (h : Nat) (p : Pos d h), m = (t.getSub p).root ∧ π = t.pathSub p
theorem fold_setSub {d h} (t : Tree d) (p : Pos d h) (s : Tree h) :
    fold s.root (t.pathSub p) = ((t.setSub p s).root : Node H)
\end{lstlisting}
\fi
\iffullversion
\begin{proof}[sketch]
Induction on the path. A non-empty path claims an internal node, so the
tree is not a tip by tag separation. Injectivity of $\Hnode$ on the
parent's preimage equates both children's hashes \emph{and} sums with the
claimed ones, and the induction hypothesis applies to the child the
direction bit selects. This is the only place the hash axioms are used.
\end{proof}
\fi

\begin{lemma}[A step is a subtree replacement]\label{lem:step}
If the current root is the root of a tree $T$ and a well-formed step is
valid from it to $r'$, its old node is the root of $T$'s subtree at some
position $p$ of the step's height, and $r'$ is the root of $T$ with that
subtree replaced by any tree whose root is the step's new node.
(\lean{Step.sound}.)
\end{lemma}

\begin{theorem}[Conservation]\label{thm:cons}
For any sequence of valid steps from $(r, S)$ to $(r', S')$,
$S' + \sum s_{\mathrm{old}} = S + \sum s_{\mathrm{new}}$; for
\tr{EXIT}$_K$, $S' + \sum_k \mathrm{payout}_k \le S$, with equality under
exact payouts. No hash assumption is needed.
(\lean{Steps.sum}, \lean{ExitK.no\_inflation}.)
\end{theorem}
\iffullversion
\begin{lstlisting}[style=leansig]
theorem Steps.sum {r r' : Node H} {ss : List (Step H)} (h : Steps r ss r') :
    r'.sum + oldSum ss = r.sum + newSum ss
theorem ExitK.no_inflation {exact} {r r'} {blocks} {out0} (h : ExitK exact r blocks r' out0) :
    out0 + payoutSum blocks ≤ r.sum      -- ExitK.exact_conservation: equality if exact
\end{lstlisting}
\fi

\begin{theorem}[Payability]\label{thm:pay}
For any tree $T$ and position $p$ holding leaf $\ell$, the honest witness
(the leaf, its path, $\Emp_0$) is a valid step from $T$'s root to the
root of $T$ with $p$ emptied, the sum falls by $\ell.\mathsf{amount}$,
and every other position is unchanged. (\lean{payable}.)
\end{theorem}
\iffullversion
\begin{lstlisting}[style=leansig]
theorem payable {d} (t : Tree d) (p : Pos d 0) (l : Leaf) (hl : t.get p = some l) :
    (leafStep (t.path p) (some l) none).valid t.root (t.set p none).root ∧
    (t.set p none).root.sum + l.amount = t.root.sum ∧ ∀ q, q ≠ p → (t.set p none).get q = t.get q
\end{lstlisting}
\fi

\begin{theorem}[Real-tree invariant]\label{thm:ground}
If the current root is the root of a tree and every step is well formed
and \emph{grounded} (its new node is the root of some tree of the step's
height), the final root is the root of a tree of the same depth.
Leaf-level steps are grounded by construction; a \tr{JOIN} graft is
grounded exactly when the operator's node has a preimage tree.
(\lean{Steps.sound}, \lean{join\_sound}.)
\end{theorem}
\iffullversion
\begin{lstlisting}[style=leansig]
theorem Steps.sound {d} (t : Tree d) {r'} {ss : List (Step H)} (h : Steps t.root ss r')
    (hwf : ∀ s ∈ ss, s.WF d) (hg : ∀ s ∈ ss, s.Grounded) : ∃ t' : Tree d, t'.root = r'
theorem join_sound {auth : Prop} {d h} (t : Tree d) (path) (new r' : Node H) (out0 : Nat)
    (hwf : path.length + h = d) (hj : Join auth h t.root path new r' out0) :
    ∃ p : Pos d h, t.getSub p = Tree.empty h ∧ out0 = t.root.sum + new.sum
      ∧ ∀ u : Tree h, u.root = new → r' = (t.setSub p u).root
\end{lstlisting}
\fi

\begin{lemma}[Path maintenance, not mechanised]\label{lem:path}
If leaf $\ell$ at $p$ with path $\pi$ folds to the root $r$, and a valid
step at a position $p'$ that is neither $p$ nor above it takes $r$ to
$r'$, then $\ell$ folds to $r'$ with the path $\pi$ in which the one
sibling on the step's path is replaced by the node the step computes at
that height.
\end{lemma}
\noindent Lemma~\ref{lem:path} needs no real tree, so it covers a path
through an opaque node; \lifted{app:uc} proves it on paper. Other
transitions have theorems of their own (Appendix~\ref{app:lean}).
Authorisation and lock times are an opaque proposition \lean{auth} in
the theorems, discharged by $\Fsig$ and $\Gclock$; which key a payout
pays (the leaf's exit key, not the evictor) is established by execution,
not by these theorems. The predicates bind the witness root and taptree
to the spent output through $\TreeSpk(r', m') = \TreeSpk(r, m)$
(\lean{witness\_root\_binds}), which reduces to the discrete logarithm of
$\NUMS$ and hash collisions when the two internal keys have opposite
signs, and to taproot binding in the random-oracle model, as in BIP-341's
own argument, when they share one (Appendix~\ref{app:lean}).

\subsection{The Composable Statement}

Let $\Pi_\tau$ be the protocol with the predicates compiled by tier
$\tau$, and $\Gledger[\Pred_\tau]$ the global ledger whose validity
predicate, for a spend of a tree output, is that tier's predicate. Let
$\Ftree|_\tau$ be $\Ftree$ restricted to what $\tau$ compiles into $m$:
the interfaces of Table~\ref{tab:tiers}, the heights $h$ and batch sizes
$K$ in the taptree, $\mathsf{exact}$ and amounts below $2^{31}$ in MID
and MIN ($\mathsf{exact}$ in CCV), no graft in the sparse profile, at
most 54 occupied positions per MID sweep, and for MIN only the dense
one-leaf \iface{EXIT} and \tr{SPLIT}, without the terminal exit. Trees
whose taptree carries \tr{REWRITE}$_h$ or \tr{DETACH}$_h$ are excluded:
neither is an interface of $\Ftree$, and their Lean theorems are all we
claim for them.

\begin{theorem}[UC realisation]\label{thm:uc}
In the idealised hash model, with taproot binding in the ROM and under
[C], for each tier $\tau$, $\Pi_\tau$ UC-realises $\Ftree|_\tau$ with
$\lat(q) = \lat_L(\lceil (\beta + q)/\kappa \rceil + 1)$, in the hybrid
model with $\Gledger[\Pred_\tau]$, $\Gclock$ and $\Fsig$ (in MIN, under
[MIN]), against a static adversary corrupting the operator and any
members, for trees without \tr{REWRITE}$_h$ and \tr{DETACH}$_h$.
\end{theorem}

\begin{simclaim}[Simulation invariant]\label{clm:inv}
After each ledger event, $\Ftree$'s partial tree has the root the tree
output commits to, and agrees with every honest party's leaf and path.
\end{simclaim}

\iffullversion
The proof is the next section.
\else
\begin{proof}[sketch of Theorem~\ref{thm:uc}]
$\Sim$ runs $\Adv$ and the honest parties internally and maintains
Claim~\ref{clm:inv}. For every accepted spend of the tree output it folds
each step's old node up its path and locates it by
Theorem~\ref{thm:binding}, first calling \iface{REVEAL} where the path
enters an opaque node; a fold that contradicts a known node yields a
collision $\Sim$ can output. It calls the matching interface on the
authoriser's behalf, checking signatures with $\Fsig$.
Lemma~\ref{lem:step} and Theorem~\ref{thm:cons} give that $\Ftree$'s
tree and amounts after the call are the transaction's, and
Lemma~\ref{lem:path} that honest paths stay valid. Honest calls are built
and posted by the protocol-aware $\Ftree$; $\Sim$ only schedules them,
within $\lat(q)$ by [C]. Ungrounded creations and grafts become opaque
nodes. The cases and hybrids are in \lifted{app:uc}.
\end{proof}
\fi

\paragraph{What the theorem leaves out.} The bytecode is matched to
$\Pred_\tau$ by 2{,}083 executable checks, not a verified compiler. Fee
pinning is outside the ledger model: a low-feerate transition early in
the chain caps the feerate behind it, a descendant hung off any payout or
change output consumes the chain's policy limit, and TRUC
transactions~\cite{bip431} cannot help, since they cap an unconfirmed
chain at two; [C] assumes this away, and cooperative batching, anchors
and sizing by exit throughput mitigate it. The operator can evict any
leaf after its lease, a cohort at about $160\vB$ per leaf, so griefing is
cheap; a longer guarantee needs a later lease at entry, and no carve can
extend it.

\section{Channel Leaves as Composition}\label{sec:channels}

A leaf whose exit key is a 2-of-2 between its owner and a counterparty
(normally the operator) can host a payment channel that exists only
off-chain and whose funding output materialises at the payout of the
\iface{EXIT} or \iface{EVICT} that removes the leaf, so a tree of such
leaves is a Lightning hub behind one UTXO. The channel protocol runs in
the $\Ftree$-hybrid model and treats the payout as its funding
transaction; \lifted{app:channels} gives scripts, state machine and costs.
The funding outpoint changes with every tree transition, so states are
signed without committing to it (\op{TX} collates the signed fields
behind a per-channel context, and CSFS checks the signature over the
hash, emulating \texttt{SIGHASH\_ANYPREVOUT}~\cite{bip118}), and the
channel uses the eltoo ratchet~\cite{eltoo,lnsymmetry} with zero-fee
version-3 transactions and an ephemeral anchor~\cite{bip431}. This needs
\op{TX} and CSFS: FULL, MID, or CCV with the channel scripts in their own
outputs.

\paragraph{Deadlines and hub size.} Settlement outputs include one per
in-flight hashed time-locked contract (HTLC). A forwarding node keeps
$\mathsf{cltv\_expiry\_delta}$ blocks between an incoming and an outgoing
HTLC's expiry, and a channel leaf needs
$\mathsf{cltv\_expiry\_delta} \ge G_{\mathrm{exit}} + 3 + \mathsf{csv\_delay} + G_{\mathrm{sweep}}$,
with $\mathsf{csv\_delay}$ the settlement's relative delay,
$G_{\mathrm{sweep}}$ the time to confirm an HTLC sweep and
$G_{\mathrm{exit}}$ the time to confirm the exit, $\lat(q)$ under [C].
With $\mathsf{csv\_delay} = 144$, $G_{\mathrm{sweep}} = 2$ and
$G_{\mathrm{exit}} = 72$ this is about 220 blocks, against 40 to 80 on
the public network. At $\lat_L = 1$, $G_{\mathrm{exit}} = 72$ needs
$\beta + q \le 71\kappa$; with $\kappa = 25$ and $\beta = 0$, about
1{,}775 channel leaves may close in one window, and larger hubs shard.
The counterparty is normally the operator, which can issue competing
spends, so the budget holds only while the member can outbid them, which
is what $\beta$ assumes. MID allows seven HTLCs per state (the 520-byte
element limit) and $2^{31}$ satoshis per tree.

\paragraph{Composition conditions.} Let $\Fchan$ be a channel
functionality in the style of Generalized Channels~\cite{genchannels}.
Three of $\Ftree$'s interfaces are too lenient for a leaf whose balance
is not the owner's alone, and each becomes a precondition: (i)
$\mathsf{exact}$ is set, so the owner cannot underfund the channel; (ii)
$\mathsf{seq}$ is the value whose successor does not fit in four bytes
($\mathtt{0xFFFFFFFF}$ under BIP-441 numerics, $\mathtt{0x7FFFFFFF}$
under \texttt{CScriptNum}, Lemma~\ref{lem:enc}), so the owner cannot
carve the leaf; (iii) the lease height is zero, giving the counterparty
\iface{EVICT} (between two members, \tr{UPDATE}$^{x}$ instead).

\begin{conjecture}\label{thm:chan}
Under [C], in the $(\Ftree, \Gledger, \Gclock, \Fsig)$-hybrid model with
conditions (i) to (iii), the channel-leaf protocol realises $\Fchan$ with
closing bound $\lat(q) + 3 + \mathsf{csv\_delay}$ for channels whose HTLC
deadlines respect the budget above.
\end{conjecture}
\noindent The proof obligations are the three conditions, the HTLC
deadline argument under [C], and the rebinding of pre-signed states
across tree transitions (\lifted{app:uc}); the state machine and the
budget run end to end on the simulator's chain model, with two blocks of
margin, but are not proved.

\section{Evaluation}\label{sec:eval}

\paragraph{Implementation.} A Python tapscript interpreter for both leaf
versions models BIP-441 numerics, \op{TX}, CSFS, the EC opcodes and
varops, computes the real BIP-341 signature message and enforces
\texttt{MINIMALDATA}; it models consensus limits, not standardness.
Every compiled predicate runs against a reference tree with positive and
negative cases per rule (forged leaf, stale root, attacker-chosen $m$,
unconserved amount, early eviction, voucher replay, and others): 956
FULL, 228 MID, 35 MIN and 864 CCV checks, failing if a script uses an
opcode outside its tier, plus 149 for channel leaves and 61 for the
hypothetical opcode of \S\ref{sec:discussion}. A Go implementation on
\texttt{btcd} and \texttt{lnd} generates the same scripts, byte-exact
against 79 golden scripts, and builds, signs and verifies every FULL
transition (42 cases); its BIP-341 signature hash equals the
simulator's.

\paragraph{The transaction model.} Every vB figure is a whole
transaction: script, witness elements and a 129-byte control block (the
eight-leaf reference script set) as measured, plus a $946\WU$ skeleton
(the tree input, a P2WPKH fee input, the tree output, one P2TR payout, a
P2WPKH change output, version, lock time and counts) and $172\WU$ per
further payout, with $\mathrm{vB} = \lceil \mathrm{WU}/4 \rceil$;
transitions without a payout (joins, updates, carves) are charged
$172\WU$ less. The witness item count and per-item length prefixes are
excluded, about 10 to $14\vB$ on a dense $D = 16$ exit (1 to 1.4\%), and
the baselines omit the same overhead. A deployment that carries the
sweeps, rewrites and variants needs 16 to 32 tapleaves, which adds 8 to
$16\vB$ to every spend.

\paragraph{Exit cost.} A dense exit (Figure~\ref{fig:plot},
Table~\ref{tab:sizes}) costs $762\vB$ at $D = 8$ and $1{,}149\vB$ at
$D = 20$, about $32\vB$ per level. One tier step costs as much as 10 (MID, $+31\%$) to 14 (MIN,
$+43\%$) levels of depth. The sparse profile at $D = 32$ with $2^{16}$
members costs about $1{,}780\vB$, 1.75 times the dense profile at
$D = 16$; its witness grows with $\log_2 N$, not $D$.

\paragraph{Comparison with transaction trees.} The dashed line of
Figure~\ref{fig:plot} is a \emph{model}: an exiter publishes $D$
transactions of about $150\vB$ (one key-path input, two P2TR outputs) and
a $111\vB$ claim, anchors and their fee children omitted, which favours
the tree. LayerTree is about 60\% smaller at $D = 16$; a radix-4 tree
needs $2{,}031\vB$, and an Ark member of a 256-member round unrolls
$1{,}311\vB$. Under mass exit a tree's interior is shared, about $261\vB$
per member at radix 2 and $191\vB$ at radix 4 with the claim, against
$158\vB$ for a cohort leaving by \tr{REWRITE}$_6$ (Table~\ref{tab:ark},
Appendix~\ref{app:eval}). The model prices neither the latency of $D$
sequential confirmations nor the larger opcode set.

\paragraph{Batching and joins.} A second exit in the same transaction
adds $665\vB$ (its marginal weight rounded up on its own, one more than

costs the operator under $3\vB$ per member, so a self-funded member's own
input dominates its entry. Off-chain, a member follows every spend of the
tree output (about 1\,kB of witness each), and the operator stores the
whole tree.

\section{Related Work}\label{sec:related}

\emph{Payment pools.} CoinPool~\cite{coinpool} is a shared UTXO with
per-user balances whose one-transaction withdrawal rests on a new opcode,
\op{MERKLESUB}; \texttt{OP\_TAPLEAF\_\allowbreak UPDATE\_\allowbreak VERIFY}~\cite{tluv} recreates a pool
output with the leaver's key and leaf removed, and \op{EVICT}~\cite{opevict}
removes unresponsive members. LayerTree reaches one-transaction exit
from opcodes proposed as general primitives, holds balances in a
Merkle-sum tree rather than keys in a taptree, and adds lease-based
eviction, cohort grafts, channel leaves and a composable statement.
\emph{Transaction trees.} Channel factories~\cite{factories} need all $N$
members to sign every change. Ark~\cite{ark}, deployed today~\cite{arkd},
batches users into rounds whose outputs are leaves of a pre-signed MuSig2
tree; covenant Ark~\cite{clark} replaces the signing with CTV or CCV
templates but keeps the tree, its unrolled exit and its expiry. Timeout
trees~\cite{timeouttrees} and SuperScalar~\cite{superscalar} add laddered
expiries and Decker-Wattenhofer factories; MATT-style
trees~\cite{matt,bip443} replace signatures by templates.
Table~\ref{tab:compare} (Appendix~\ref{app:eval}) compares them. \emph{Beyond Bitcoin.} Plasma's forced exits~\cite{plasma} prove a
balance against a committed root, enforced by a contract. Proofs of
liabilities~\cite{gpol,brokensolvency} use Merkle-sum trees, where a node
that hashes only its children's total admits the inflation that hashing
each child's sum avoids. None of these states its guarantees as a
functionality; we build on the ledger model of~\cite{bmtz17} and the
channel functionalities of~\cite{genchannels,gscn}. \emph{Components.}
The Merkle-sum sparse Merkle tree is Taproot Assets'~\cite{mssmt},
truncated and verified in script; the data-tweaked key follows
BIP-443~\cite{bip443}; the generator-key signature is
Poelstra's~\cite{catschnorr}, and its ECDSA analogue has been used on
Bitcoin Cash as \texttt{OP\_PUSH\_TX}. Liquid's tapscript~\cite{elements} has \op{CAT}, CSFS, per-field
introspection and 64-bit arithmetic, so MID is close to expressible
there; Simplicity~\cite{simplicity} would express the predicates
directly.

\section{Discussion and Limitations}\label{sec:discussion}

The functionality is deliberately modest, and its liveness more so:
all activity is serialised through one output, so an honest exit's delay
is set by policy and fees, which [C] names rather than derives. Cluster mempool~\cite{clustermempool} replaces the 25-transaction
chain limit with per-cluster limits, which raises $\kappa$ for a
cooperative tree but shares the cluster with every descendant anyone
attaches. Two open design changes would narrow the dependence: a relative
lock on transitions that remove no value, so that only removals chain,
and an exit authorised by a CSFS signature over $m$, the leaf and the
payout rather than the outpoint, so a tower could rebuild and rebroadcast
it. A Liquid prototype of MID is the obvious next experiment; a
hypothetical native Merkle-sum opcode (simulator only) takes \tr{EXIT}$_1$
to 252 B of script at every depth.

\section{Conclusion}

LayerTree specifies a shared output by what it lets members do (join,
leave alone, be evicted after a lease, be swept as a cohort) and realises
it with a tree kept off-chain as data: a one-transaction exit of about a
kilobyte, no pre-signing, no expiry of the shared output, from proposed
opcodes; its price is that all activity funnels through one UTXO. Future
work: a verified compiler, a proof of Conjecture~\ref{thm:chan},
mechanising Lemma~\ref{lem:path}, and a P model~\cite{plang}.
